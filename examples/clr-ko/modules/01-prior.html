중간 언어의 계보논문 1절, 참고문헌

중간 언어 하나로 여러 언어와 여러 기계를 잇자는 생각은 오래되었다. 논문 1절은 그 예로 UNCOL(Universal Computer Oriented Language), UCSD P-code(UCSD Pascal의 중간 코드), ANDF(Architecture Neutral Distribution Format), AS/400, 자바 가상 머신(Java Virtual Machine, JVM)을 들고, 마지막에 공통 언어 기반(Common Language Infrastructure, CLI)을 놓는다. 그림은 이 흐름을 논문 참고문헌의 연도로 나타낸 것이다.

연도는 논문 참고문헌의 발표 연도이다. P-code와 AS/400은 그 시스템을 다룬 문헌의 연도이므로 시스템이 처음 나온 해와 다를 수 있다.

계보의 앞쪽은 대체로 한 언어를 여러 기계로 옮기거나 기계와 무관한 배포 형식을 만드는 데 집중했다. CLI는 반대로 여러 언어를 한 실행 환경에 모으는 쪽에 무게를 둔다. 다음 쪽의 계보 트리는 각 갈래에서 이어받은 것과 달라진 것을 정리한다.

요약

중간 언어 계보는 1958년 UNCOL 제안에서 시작해 P-code, ANDF, AS/400, JVM을 거쳐 2001년 CLI로 이어진다.

새로운 점

앞선 시스템이 한 언어나 한 배포 형식에 맞췄다면, CLI는 여러 언어의 기본 연산을 처음부터 명령어로 넣었다고 논문은 주장한다.

출발점

“달라진 것”은 논문이 CLI의 특징으로 든 내용을 각 갈래에 대응시킨 해석이다. 노드를 누르면 참고문헌 정보가 나온다.

요약

CLI는 UNCOL의 공통 중간 언어라는 생각과 JVM의 고수준 런타임을 이어받되, 여러 언어의 기본 연산을 처음부터 넣는다고 주장한다.

JVM이 택해진 이유와 저자의 주장논문 1절

논문은 많은 언어 구현자가 JVM을 택한 이유로 고수준 런타임(GC, 스레드, 보안), 넓은 보급, 풍부한 Java 라이브러리를 든다.

그러나 저자들은 JVM이 Java에는 훌륭한 대상이지만 다중 언어 플랫폼으로는 본질적으로 최적이 아니라고 주장한다. 그림은 논문이 든 문제를 두 묶음으로 나눈 것이다. 강조한 tail call(꼬리 호출, 함수의 마지막 동작인 호출)은 CLI가 언어 연구자의 의견을 받아 명령어로 추가한 기능이다.

그림은 논문 1절이 든 JVM의 문제를 두 묶음으로 나타낸 것이다. ㄴ의 목록은 논문의 예시이며 전부는 아니다.

요약

JVM은 런타임, 보급, 라이브러리 때문에 택해졌지만, 저자들은 타입 안전하지 않은 기능과 여러 기본 연산이 없어 다중 언어에 불리하다고 주장한다.

당시 JVM에서는 참조 전달, tail call, 공용체, 오버플로 감지, 긴 분기, 다차원 배열을 우회책으로 흉내 내야 했다.

탐구 자료재귀 루프를 세 방식으로 돌리기논문 1, 8.1절

Scheme처럼 재귀가 반복의 유일한 수단인 언어에서는 단서 칸의 count처럼 마지막에 자기 자신을 부르는 함수가 반복문 구실을 한다. 그림은 이 예시 함수를 세 방식으로 실행할 때의 스택 프레임을 나타낸 개념 그림이다.

그림은 예시 함수 count(3)의 스택 프레임을 그린 개념 그림이다. 회색 틀은 스택이고 아래가 바닥이다.

trampoline은 함수가 자기를 직접 부르지 않고 “다음에 부를 호출”을 객체로 돌려주면 바깥 반복문이 대신 부르는 기법이다. 스택은 지키지만 단계마다 객체를 만들고 반복문을 거치는 비용이 든다(해석). CLI의 tail. 접두사는 이 비용을 없애지만, 신뢰하지 않는 코드가 신뢰하는 코드를 부르는 보안 경계에서는 프레임을 완전히 버릴 수 없다(6단원).

요약

JVM은 trampoline으로 스택을 지키며 객체 생성 비용을 내고, CLI는 tail.로 프레임을 교체하지만 보안 경계에서는 제약이 있다.

그래서 CLI는 무엇을 했나논문 1, 12절

논문에 따르면 Microsoft는 CLI 개발 초기부터 상업·학계의 언어 구현자와 협력했다. tail. 명령어는 그 협력에서 언어 연구자의 의견을 받아 직접 추가한 것이다. 표는 두 플랫폼을 논문의 서술로 비교한 것이다.

표는 당시 JVM과 CLI를 다섯 가지 기준으로 비교한 것이다. CLI 열은 저자들의 주장이다.

언어 구현자의 의견Java 밖 기능은 우회책으로 해결개발 초기부터 협력, tail call 명령어 추가

핵심 비교 JVM은 Java에 맞춘 기계에 다른 언어를 끼워 넣고, CLI는 여러 언어의 기본 연산을 처음부터 명령어로 넣었다는 것이 논문의 주장이다.

요약

CLI는 언어 구현자와 협력해 다중 언어용 명령어를 처음부터 넣었다고 주장하지만, 이는 실험 없는 이해관계자의 주장이다.

핵심 정리
  1. 중간 언어 계보는 UNCOL에서 시작해 JVM을 거쳐 CLI로 이어진다.
  2. 당시 JVM은 참조 전달, tail call, 공용체 등을 우회책으로 흉내 내야 했다.
  3. 우회책은 할당이나 검사 같은 비용을 남긴다.
  4. CLI의 우위는 실험이 아닌 저자의 주장이다.
  5. 우회책 문항은 “무엇을 대신 만드는가”부터 찾아라.
