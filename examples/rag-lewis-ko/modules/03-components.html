retriever: DPR논문 2.2절

RAG의 retriever(검색기)는 DPR(Dense Passage Retriever)이다. DPR은 질문과 문서를 서로 다른 BERT(양방향 인코더 사전학습 모델)로 따로 벡터로 바꾸는 bi-encoder(query와 문서를 따로 임베딩) 구조이다. 두 인코더는 모두 BERT-base 크기이다.

$$p_\eta(z|x) \propto \mathit{exp}\big(\boldsymbol{d}(z)^{\top}\boldsymbol{q}(x)\big), \qquad \boldsymbol{d}(z) = \mathit{BERT}_d(z), \quad \boldsymbol{q}(x) = \mathit{BERT}_q(x)$$

여기서 $\boldsymbol{q}(x)$는 query encoder(질의 인코더)가 만든 질문 벡터, $\boldsymbol{d}(z)$는 document encoder(문서 인코더)가 만든 문서 벡터이다. 두 벡터의 내적(Inner Product)이 클수록 문서 확률이 커지며, 비례 기호 ∝는 top-k 문서끼리 합이 1이 되게 나눈다는 뜻이다.

질문과 문서가 서로를 보지 않고 벡터만 만나므로, 문서 벡터는 질문이 오기 전에 미리 계산해 둘 수 있다. 이것이 2,100만 문서를 검색할 수 있는 이유이자, 두 문장을 함께 읽는 모델보다 세밀한 비교를 하지 못한다는 대가이다. 논문은 DPR이 학습해 둔 bi-encoder로 retriever를 초기화했고, 이 DPR은 TriviaQA와 Natural Questions에서 답이 든 문서를 찾도록 학습된 모델이다.

요약

DPR은 질문과 문서를 각각 BERT로 벡터화하고 두 벡터의 내적으로 문서 확률을 정한다.

MIPS와 문서 색인의 규모논문 2.2, 3절, 부록 C

내적이 가장 큰 top-k(상위 $k$개) 문서를 고르는 일은 MIPS(Maximum Inner Product Search, 최대 내적 검색) 문제이다. 모든 문서와 내적을 계산하면 질문 하나에 2,100만 번을 계산해야 한다. 논문은 FAISS(벡터 검색 라이브러리)의 HNSW(Hierarchical Navigable Small World, 그래프 기반 근사 최근접 탐색) 색인으로 이 문제를 근사 최근접 이웃 탐색(Approximate Nearest Neighbor, ANN)으로 풀어 준선형 시간에 답을 얻는다.

근사이므로 빠른 대신 정확한 top-k와 다른 문서가 섞일 수 있다. 메모리도 든다. 논문은 색인 벡터를 CPU에 두었다.

generator: BART논문 2.3절

RAG의 generator(생성기)는 BART(잡음 제거로 사전학습한 seq2seq 모델)의 large 판이며 파라미터가 4억 개 규모(400M)이다. BART는 seq2seq(Sequence-to-Sequence, 입력 문장을 출력 문장으로 바꾸는 모델)로, 망가뜨린 문장을 되살리는 잡음 제거 과제로 사전학습되었다.

RAG는 질문 $x$와 검색 문서 $z$를 단순히 이어 붙여 BART에 넣는다. 디코더는 자기회귀(Autoregressive) 방식으로 답을 한 토큰씩 쓴다. 이 파라미터 $\theta$가 RAG의 parametric memory(모델 파라미터에 저장된 기억)이다.

대가는 계산량이다. 문서마다 [질문; 문서]를 따로 읽으므로 문서가 $k$개면 generator를 $k$번 돌려야 하고, 문서 100단어가 붙어 입력도 길어진다.

요약

BART generator는 질문과 문서를 이어 붙인 입력을 읽고 답을 한 토큰씩 쓰며, 문서 수만큼 계산을 되풀이한다.

학습: 무엇을 갱신하는가논문 2.4절, 부록 G

학습 데이터에는 질문 $x_j$와 정답 $y_j$의 쌍만 있고, 어떤 문서를 검색해야 하는지는 없다. 그래서 RAG는 문서를 주변화한 주변 가능도(Marginal Likelihood)의 로그에 음수를 붙인 값을 손실로 삼아 Adam으로 최소화한다.

$$\mathcal{L} = \sum_{j} -\mathit{log}\, p(y_j|x_j)$$

3단원 따라가기 예시의 $p(y|x)\approx 0.0147$이면 손실은 $-\mathit{log}\,0.0147 \approx 4.22$이다. 이 값을 줄이려면 정답을 잘 설명하는 문서의 $p_\eta(z|x)$를 키워야 하므로, 정답 문서 레이블 없이도 retriever가 학습된다. 이것이 end-to-end 학습(입력부터 출력까지 한 번에 학습)이다.

fine-tuning(미세 조정) 동안 갱신하는 것은 query encoder와 BART뿐이다. 논문 부록 G는 학습 가능 파라미터를 626M으로 적지만, 그중 문서 인코더 110M은 실제로 갱신하지 않으므로 갱신되는 양은 110M + 406M = 516M이다.

요약

RAG는 음의 주변 로그 가능도를 줄이며 query encoder와 BART만 갱신하고, 문서 인코더와 색인은 고정한다.

보충 설명

RAG-Token은 토큰마다 문서를 가중합한 확률 $p'_\theta(y_i|x,y_{1:i-1})$을 다음 토큰 확률로 보고 보통의 beam search(빔 탐색)에 넣으면 된다.

탐구 자료의사코드 단계별 풀이: RAG-Sequence 디코딩논문 2.5절

RAG-Sequence의 확률은 토큰 단위로 나뉘지 않으므로, 문서마다 beam search를 돌려 후보를 모은 뒤 다시 점수를 매긴다. 버튼을 눌러 한 줄씩 보시오.

알고리즘 INPUT: x, z_1..z_k, b // 입력 FOR EACH z_i: B_i = BEAM(x, z_i, b) Y = UNION(B_1, ..., B_k) // 후보 FOR EACH y IN Y, z_i DO // 모든 쌍 IF y IN B_i THEN s = 저장값 ELSE IF THOROUGH: s = FWD(y, x, z_i) ELSE s = 0 // Fast score(y) = SUM(p_eta(z_i|x) * s) OUTPUT: ARGMAX score(y) // 출력
설명

질문, 문서 $k$개, beam 크기 $b$를 받는다.

문서 하나씩 따로 beam search를 돌려 후보 $b$개를 얻는다.

모든 문서의 후보를 합쳐 후보 집합 $Y$를 만든다.

주변화하려면 모든 (후보, 문서) 쌍의 확률이 필요하다.

그 문서의 beam에 있던 후보는 이미 계산했다.

Thorough Decoding(빠진 후보도 다시 계산)은 forward pass(순전파)를 더 돌려 구한다.

Fast Decoding(빠진 후보는 확률 0으로 근사)은 0으로 두어 계산을 아낀다.

문서 확률로 가중합해 $p(y|x)$를 구한다.

점수가 가장 큰 후보를 답으로 낸다.

요약

RAG-Sequence는 문서마다 beam search로 후보를 모은 뒤, 빠진 확률을 다시 계산하거나(Thorough) 0으로 두고(Fast) 주변화한다.

디코딩 비용과 실제 설정논문 2.5절, 부록 A

예시로 문서 $k=4$개, beam 크기 $b=2$이면 beam search에서 (후보, 문서) 쌍 8개의 확률이 나온다. 후보를 합친 결과가 $|Y|=5$개라면 주변화에 필요한 확률은 $5\times4=20$개이므로, Thorough Decoding은 forward pass를 $20-8=12$번 더 돌린다. Fast Decoding은 추가 계산이 0번이지만 빠진 12개를 0으로 두므로 확률을 낮게 어림한다.

그림은 예시에서 두 방식이 쓰는 forward pass 수를 나타낸 것이다(색칠한 부분이 추가 계산).

출력이 길수록 $|Y|$가 커져 추가 계산이 늘어난다. 오픈 도메인 QA에서는 문서 50개와 greedy decoding(매 단계 가장 높은 토큰 선택)를 썼으므로, 예를 들어 $|Y|=10$이면 $10\times50-50=450$번을 더 계산한다(예시 값).

요약

Thorough Decoding은 후보와 문서가 많을수록 추가 forward pass가 늘어 답이 짧은 QA에만 쓰고, 생성 과제에는 Fast Decoding을 썼다.

핵심 정리
  1. DPR은 BERT 두 개로 질문과 문서를 따로 벡터화하고, 내적이 큰 top-k를 FAISS의 HNSW 근사 MIPS로 찾는다.
  2. BART generator는 [질문; 문서]를 읽고 답을 쓰며, 문서마다 따로 계산한다.
  3. 음의 주변 로그 가능도로 query encoder와 BART만 학습하고, 문서 인코더와 색인은 고정한다.
  4. RAG-Token은 일반 beam search, RAG-Sequence는 Thorough 또는 Fast Decoding을 쓴다.
  5. 추가 계산량은 (후보 수 × 문서 수) − (beam에서 이미 구한 쌍 수)로 세라.
