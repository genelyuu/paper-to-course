# 신경·기호 AI 주간 연구·교육 브리핑

## 1. 조사 범위와 판정 기준

- **기준일:** 2026년 10월 9일
- **검색 기간:** 2026년 10월 2일~8일 공개 또는 실질 개정분
- **검색원:** arXiv의 cs.AI·cs.LO·cs.LG·cs.MA·cs.CL, 공개 학회 정보, 논문에 연결된 코드·데이터 저장소
- **검색식 계열:**  
  `neuro-symbolic/neurosymbolic`, `ontology learning/reasoning`, `logical form/semantic parsing`, `knowledge graph reasoning`, `multi-agent trust/safety/verification/evaluation`, `formal verification agent`
- **포함:** 새로운 방법·벤치마크·실증 결과·체계적 분류를 제공하고 원문 관련성을 확인한 연구
- **제외:** 단순히 “ontology”나 “multi-agent”를 언급한 연구, 일반 GNN·다중로봇 경로계획처럼 신뢰·기호추론과 직접 관련 없는 자료, 원문을 확인할 수 없는 2차 요약
- **중복 처리:** arXiv와 학회 판본은 하나로 합쳤다.
- **한계:** 검색 가능한 최신 색인에 기반한 폭넓은 조사이지 모든 출판 데이터베이스의 체계적 전수조사는 아니다. 아래 수치는 독립 재현값이 아닌 **저자 보고값**이다.

이번 기간에는 직접 관련 자료 **7건**을 확인했다. **문장→논리 표현 또는 OWL 온톨지 생성 자체를 주제로 새로 공개된 직접 연구는 발견하지 못했다.** 다만 규칙 언어 선택, 확률적 기호추론, 증명 가능한 생성 결과, KG 근거 추적과 관련된 자료가 다수 나왔다.

## 3. 직접 적용 우선순위 3건

### ① BAR: 근거가 있는 KG 탐색

권장 파이프라인은 다음과 같다.

```text
원문 문장
→ 논리 표현·후보 트리플
→ provenance·지지점수 부착
→ 질문별 부분 KG
→ 계획–탐색–검증
→ 출처가 있는 답 또는 보류
```

필요 데이터:

- 기존 문장–논리식–트리플 정답쌍
- 각 트리플을 지지하는 문장 ID
- 간선별 출처 신뢰등급
- competency question과 정답 추론 경로

최소 검증 실험:

- 비교군: 전체 KG 검색 / top-k 검색 / 비용제약 검색 / 비용제약+검증
- 지표: 답 정확도, 근거 precision·recall, unsupported-triple rate, 탐색 간선 수, 토큰 비용
- 핵심 ablation: provenance 제거, 지지점수 제거, verifier 제거
- 의료 성과가 아니라 **근거 있는 추론 구조**만 전이해야 한다.

### ② LeanPlan: 생성과 검증의 분업

사용자 연구에서는 Lean 대신 OWL reasoner를 활용해 다음과 같이 옮길 수 있다.

1. Transformer가 논리 표현과 OWL 공리를 생성한다.
2. 문법 검사기가 파싱 가능성을 검사한다.
3. HermiT/ELK가 일관성과 함의를 검사한다.
4. 별도 evidence verifier가 원문이 공리를 실제로 지지하는지 검사한다.
5. 실패 유형을 `syntax`, `logical`, `semantic-alignment`로 구분한다.

최소 실험은 100~200개 문장에 인위적으로 세 오류 유형을 균형 삽입하고, 단계별 검출 recall과 오탐률을 측정하는 것이다. reasoner 통과율만 보고하면 의미 변환 오류를 놓칠 수 있다.

### ③ BazaarBench: 상태 기반 멀티에이전트 신뢰 평가

온톨로지 협업 환경에서 시장의 소유권·약속 레코드를 다음으로 치환할 수 있다.

| BazaarBench 상태 | 온톨로지 협업 상태 |
|---|---|
| 상품 소유권 | 공리 작성·수정 권한 |
| 상품 상태 | 공리 검증 상태 |
| 거래 약속 | 에이전트가 주장한 트리플 |
| 재고 없음 | 근거 문장 없음 |
| 중복 판매 | 상충 공리 동시 승인 |
| 평판 | 과거 검증 정확도 |

최소 실험:

- 3개 에이전트: 추출자, 검증자, 병합자
- 50개 정상 문장 + 25개 모순 문장 + 25개 근거 없는 지시
- 조건: 정상 / 시간 압박 / 악의적 에이전트
- 지표: 무근거 공리 승인률, 모순 병합률, 권한 위반률, 최종 ontology consistency, 올바른 abstention 비율

## 4. 교육공학적 적용안

다음은 논문에서 교육 효과가 검증됐다는 뜻이 아니라, 연구 결과를 근거로 한 **제안 수업 설계**다.

| 대상·목표 | 활동 | 평가 및 피드백 |
|---|---|---|
| 대학원생·산업 AI 연구자; Datalog·ASP·OWL의 차이를 설명한다 | 같은 요구사항을 세 표현으로 작성하고 open-world/closed-world 차이를 비교 | 표현 선택과 근거를 4점 루브릭으로 평가. “모든 규칙 언어가 동일한 추론을 한다”는 오개념에는 부재 정보 예제를 제시 |
| 문장→논리 변환 오류를 세 유형으로 분류한다 | 파싱 오류, 논리 모순, 원문 불일치 공리를 각각 진단 | 오류 유형·근거·수정안이 모두 맞으면 달성. reasoner 성공을 의미 충실성과 혼동하면 원문 대조를 요구 |
| provenance가 있는 KG 추론을 설계한다 | 동일 답을 내는 출처 있음/없음 경로를 비교 | 답 정확도와 citation precision을 별도로 계산해야 통과 |
| 멀티에이전트 신뢰를 행동 결과로 평가한다 | 추출·검증·병합 에이전트 로그에서 무근거 승인과 권한 위반 탐지 | 발화의 설득력이 아닌 세계 상태·정책·최종 변경을 근거로 판정 |
| 장기 실행 로그에서 주장 근거를 역추적한다 | Transect형 타임라인에서 최종 공리의 최초 생성·검증·수정 턴 추적 | 모든 공리에 source turn과 validator를 연결하면 달성 |

권장 공통 루브릭은 **형식 정확성 25%, 의미 충실성 25%, provenance 20%, 추론 검증 20%, 한계 설명 10%**다.

## 5. 한국어 정보 기반 미니 튜토리얼

### 주제: 에이전트의 말을 믿지 말고 상태와 약속을 검증하기

**형태:** 공개 자료 기반 비실행형 축소 실습  
BazaarBench는 코드·시뮬레이터·저장된 상태·357,608회 호출 기록을 공개했지만, 이번 브리핑에서는 저장소 설치와 전체 실험을 직접 실행하지 않았다. 따라서 아래 예시는 논문 재현 완료 결과가 아니다. 공개 원문과 자료 링크는 [arXiv 논문 페이지](https://arxiv.org/abs/2610.06748)의 Code/Data 항목에서 확인할 수 있다.

### 개념

에이전트가 “이 트리플은 검증됐다”고 말하는 것과 실제로 다음 조건을 만족하는 것은 다르다.

```text
근거 문장이 존재한다
∧ 에이전트에게 수정 권한이 있다
∧ 기존 공리와 모순되지 않는다
∧ 검증 단계가 실제로 수행됐다
```

### 준비물

- 표 계산기 또는 Python을 읽을 수 있는 환경
- 다음 열을 가진 작은 CSV 또는 표:

```text
claim_id, agent, source_sentence, axiom,
has_evidence, authorized, reasoner_passed, promised_status, final_status
```

### 최소 예제

| claim | 에이전트 주장 | 실제 상태 |
|---|---|---|
| C1 | “근거 확인 완료” | 근거 있음, 권한 있음, 추론 통과 |
| C2 | “검증 완료” | 근거 없음, 권한 있음 |
| C3 | “병합 승인” | 근거 있음, 권한 없음 |
| C4 | “일관성 확인” | 근거 있음, 권한 있음, reasoner 실패 |

검증 규칙:

```text
accept =
has_evidence
AND authorized
AND reasoner_passed
```

### 단계별 실습

1. 각 claim의 에이전트 발화만 보고 1차 판정을 기록한다.
2. 실제 상태 열을 공개하고 위 규칙으로 판정을 다시 계산한다.
3. 두 판정이 다른 사례를 `unsupported`, `unauthorized`, `inconsistent`로 분류한다.
4. 각 오류를 발견하려면 어떤 로그가 필요했는지 적는다.
5. 최종 시스템 지표를 계산한다.

```text
무근거 승인률 = 승인된 claim 중 has_evidence=False 비율
권한 위반률 = 적용된 claim 중 authorized=False 비율
모순 병합률 = 적용된 claim 중 reasoner_passed=False 비율
```

### 예상 출력

- C1: 승인
- C2: 거부 — 근거 없음
- C3: 거부 — 권한 없음
- C4: 거부 — 논리적 일관성 실패

### 검증 문항과 정답 기준

1. **검증자 에이전트의 신뢰도가 높으면 C2를 승인해도 되는가?**  
   정답: 아니다. 평판은 해당 주장의 근거 존재를 대체하지 않는다.

2. **C4가 원문을 정확히 반영하면 그대로 병합할 수 있는가?**  
   정답: 아니다. 원문 충실성과 전체 온톨로지 일관성은 별도 조건이다.

3. **모든 구조 검사를 통과하면 공리가 참인가?**  
   정답: 보장되지 않는다. 잘못된 원문, 부정확한 출처 또는 잘못된 형식화가 남을 수 있다.

### 평가상 주의점

- LLM judge 판정과 결정적 상태 검사를 구분한다.
- 에이전트의 자신감이나 장황한 설명을 근거 품질로 사용하지 않는다.
- `reasoner_passed=True`는 원문 의미 보존을 뜻하지 않는다.
- 공격 조건의 수익·과제 성공률 상승을 신뢰성 향상으로 해석하지 않는다.
- 실제 연구에서는 claim 단위뿐 아니라 에이전트·문서·온톨로지 단위 신뢰구간도 보고해야 한다.

이번 주 연구 흐름의 공통점은 분명하다. **생성 성능 자체보다 근거의 출처, 기계 검증 가능한 제약, 장기 실행의 관측 가능성, 실제 상태와의 일치 여부를 별도 평가축으로 만드는 방향**이 강해지고 있다. 사용자의 연구에서는 이를 `문장 근거 → 논리 표현 → 공리 → 추론 경로 → 에이전트 결정 이력`의 완전한 provenance 체계로 통합하는 것이 가장 가치 있는 다음 단계다.
