# 신경·기호 AI 연구·교육 브리핑

**이번 조사에서 가장 직접적인 자료는 10월 10일 정식 출판된 온톨로지 기반 GraphRAG 연구**입니다. 온톨로지·규칙으로 구축한 그래프와 언어모델을 분리하고, 답변뿐 아니라 그래프 간선의 출처도 평가했습니다. 멀티에이전트 쪽에서는 *검증 가능한 협업 정보*, *구조화된 권한 기록*, *도구 결과의 실행 맥락 결속*이 실험 가능한 연구 주제로 두드러졌습니다.

## 조사 기준

2026년 **10월 9~15일** 새로 공개되거나 실질적으로 개정된 자료를 arXiv, 출판사 원문, 저자 공개 저장소에서 검색했다. 검색식은 `ontology reasoning/generation`, `neurosymbolic`, `natural language to logic`, `knowledge graph reasoning`, `multi-agent trust/verification/safety`와 관련어의 조합이다. 제목뿐 아니라 초록·원문에서 형식 지식 또는 에이전트 신뢰와의 관련성을 확인했고, 같은 연구의 판본은 합쳤다. 단순 키워드 일치, 주제 밖 다중로봇 연구, 실질적 변경을 확인할 수 없는 판본 수정은 제외했다.

아래는 **확인된 관련 자료 목록이지 전 출판처의 전수조사 결과는 아니다.** 수치는 모두 저자 보고값이다. arXiv DOI는 프리프린트 식별용이며 동료심사를 뜻하지 않는다. arXiv 자료는 별도 표시가 없으면 해당 날짜의 **v1·심사 여부 미확인**이다.

## 사용자 연구에 적용할 3건

### 1. 온톨로지 기반 GraphRAG — 추출 결과의 근거 보존

기존 `문장→논리 표현→트리플`에 `source_document`, `source_span`, `extraction_version`, `inference_rule`, `derived_from`을 추가한다. 원문에서 직접 추출한 간선과 reasoner가 도출한 간선을 구별한다. 논문 [공식 저장소](https://github.com/CosmoIknosLab/ontology-guided-graphrag)는 온톨로지, 평가 질문·판정 결과, 코드 구조와 재계산 명령을 공개한다.

최소 실험은 사용자 보유 문장–트리플 데이터에서 질문 30개를 별도 보류하고, **기존 트리플 검색 / 일반 RAG / 출처가 있는 온톨로지 그래프**를 같은 생성 모델로 비교하는 것이다. 답 정확도뿐 아니라 근거 간선 precision, 출처 추적률, 추론 경로 정확도, 무근거 답변율을 보고한다. 논문의 100% 간선 추적률을 답변의 100% 사실성으로 해석해서는 안 된다.

### 2. CoSIR — 에이전트 간 정보의 실제 기여 측정

추출자·검증자·병합자를 구성하고 각 에이전트에게 서로 다른 원문 또는 온톨로지 제약을 제공한다. 메시지별로 “새롭고 참인 근거를 전달했는가”, “요청이 부족한 정보를 겨냥했는가”, “수신자가 최종 공리 결정에 사용했는가”를 판정한다.

최소 실험은 **근거 공유 보상 없음 / 최종 트리플 F1 보상만 / 메시지 기여도 보상**의 세 조건을 같은 100개 문장에 비교하는 것이다. 최종 F1, 근거 누락률, 허위 정보 공유율, 메시지·토큰 비용을 함께 측정한다. 논문의 보상식을 바로 신뢰점수로 사용하지 말고, 권한 위반과 출처 위조를 별도 검사해야 한다.

### 3. TRAP — 추론·도구 결과의 맥락 결속

에이전트가 받은 “일관성 검사 통과” 결과를 다른 온톨로지 버전에 재사용하는 시험을 만든다. 결과 객체에 `task_id`, `ontology_hash`, `reasoner_version`, `call_id`, `issued_at`을 붙이고 현재 요청과 일치할 때만 수락한다.

최소 실험은 동일 공리를 대상으로 **정상 결과 / 다른 버전의 결과 / 다른 작업의 결과 / 오래된 캐시 결과**를 주입하는 것이다. 최종 공리 오류율과 정당한 재시도 차단률을 모두 측정한다. 이 설계는 TRAP에서 관찰된 오류 유형을 사용자 시스템에 옮긴 **제안**이지, 해당 논문이 OWL 추론기를 시험했다는 뜻은 아니다.

## 교육공학적 적용

아래는 **논문에서 입증된 교육 효과가 아닌 수업 설계 제안**이다. 대상은 Python·기초 ML, 주어–관계–목적어 표현과 precision/recall을 아는 대학원생 또는 산업 AI 학습자다.

| 연구 주제 | 관찰 가능한 학습목표와 활동 | 평가 문항·오개념 피드백 |
|---|---|---|
| 온톨로지 GraphRAG | 직접 추출 간선과 추론 간선에 서로 다른 출처·규칙을 기록하고 질문의 근거 경로를 재구성한다 | “모든 간선에 출처가 있으면 답은 참인가?” → 아니다. 출처의 정확성과 추론 규칙의 타당성을 별도 검사한다. |
| 해석 가능한 세계모델 | 정적 트리플만으로 표현하기 어려운 `이전·이후·항상` 조건을 찾고 시간 규칙을 작성한다 | 상태 하나의 정확도와 시간 전개 계획 성공률을 구별하면 달성한다. |
| CoSIR | 세 에이전트의 메시지에서 신규·중복·허위 근거를 분류한다 | 메시지 수가 아닌 최종 결정에 사용된 참인 근거를 세도록 피드백한다. |
| 검증 가능한 권한 기록 | “승인했다”는 발화와 실제 승인 이벤트·권한 토큰을 대조한다 | 구조화 기록이 없는 승인을 보류할 수 있어야 한다. |
| TRAP | 같은 결과값이 서로 다른 `task_id`·온톨로지 버전에서 안전한지 판정한다 | “도구가 진짜 반환했으니 재사용해도 된다”는 답에는 호출 맥락을 대조하게 한다. |
| 오래된 메모리 | 온톨로지 공리 변경 뒤 영향을 받는 캐시 답을 찾아 무효화한다 | 개정 전후 질의를 모두 정확히 판정하면 달성한다. |
| 에이전트 연쇄 영향 | 원자료 공유, 요약 전달, 결론만 전달하는 조건의 결과 차이를 비교한다 | 에이전트 수만으로 안전성을 설명하지 않고 정보 접근·handoff를 명시해야 한다. |

공통 루브릭은 **형식 정확성 25%, 원문·출처 충실성 25%, 추론·상태 검증 25%, 실패 유형 설명 15%, 재현 가능성 10%**로 운영할 수 있다.

## 정보 기반 미니 튜토리얼: GraphRAG의 발표 수치를 다시 계산하기

**출처·버전:** 2026년 10월 10일 출판된 [논문 원문](https://doi.org/10.1007/s00521-026-12495-0)과 저자의 [공식 재현 저장소](https://github.com/CosmoIknosLab/ontology-guided-graphrag). 저장소에는 평가 질문·판정 파일·재계산 명령이 안내돼 있다. **이번 브리핑에서는 코드를 실행하지 않았으므로 아래는 저자 안내에 따른 실행 절차이며, 실행 검증 결과가 아니다.**

개념은 단순하다. 동일 질문에 대해 두 시스템의 답을 비교한 뒤, 동률을 제외한 판정 중 온톨로지 그래프 답이 선택된 비율을 *win rate*로 계산한다. 이는 정답률이나 상대적 성능 향상률과 다르다.

준비물은 Git, Python, 공개 저장소의 `results/` 판정 파일이다. 전체 그래프 구축에는 ArangoDB·외부 모델 설정이 추가로 필요하지만, 저자 안내상 **발표된 평가표 재계산에는 API 키가 필요하지 않다**.

저장소의 안내에 따른 절차:

```bash
git clone https://github.com/CosmoIknosLab/ontology-guided-graphrag.git
cd ontology-guided-graphrag
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
ontorag eval reproduce
pytest
```

저장소가 제시한 **예상값**은 웹검색 비교의 탐색형 질문에서 정확성 승률 약 **79%**, 완전성 **83%**, 연결성 **100%**다. 실무형 질문의 practical applicability는 **35%**다. 명령 실행 시 일부 결과 파일의 부재가 표시될 수 있는지, 현재 저장소 상태에서 전 표가 재현되는지는 직접 확인하지 못했다.

검증 질문은 두 가지다.

1. “79%는 정확도가 79%p 올랐다는 뜻인가?” — **아니다.** 동률을 제외한 쌍대 판정의 승률이다.
2. “간선 출처 추적률 100%면 생성된 모든 문장이 옳은가?” — **아니다.** 그래프 기질의 출처 추적과 답변의 사실성은 별도 평가다.

수업에서는 재계산된 값뿐 아니라 **판정 파일 수, 동률 처리, judge 기준, 같은 모델 계열의 평가 편향**을 함께 보고하게 해야 한다. 그래프 전체를 새로 구축하거나 모델 답변을 재생성하면 원 논문의 수치가 비트 단위로 동일하게 나오리라 기대해서는 안 된다.
