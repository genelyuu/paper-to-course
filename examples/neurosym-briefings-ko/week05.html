2. 이번 주 핵심 판단

가장 직접적인 자료는 세 편이다.

1. AgentOnto

데이터베이스·문서·예제 작업을 하나의 갱신 가능한 분석 온톨로지로 통합한다. 사용자의 제조·투자엔지니어링 문서 및 AACE 비용 온톨로지에 가장 직접적이다.

2. HeritageKGBench 연구

LLM 문장→복합 온톨로지 트리플 변환에서 검증기를 뒤에 붙이는 것만으로는 상류 추출 오류가 복구되지 않는다는 강한 부정적 결과를 제시한다.

3. PerMIT

공유 메모리와 에이전트 간 지식을 신뢰·검증하는 구체적 구조, 공격 실험 및 Lean 4 정리를 제공한다.

또한 이번 주에는 자연어→LTL→반례→자연어 수정의 폐루프를 구현한 SpecRepair, OWL/Turtle 산출물과 전체 재현 코드를 공개한 NIKG가 교육·프로토타이핑 관점에서 특히 유용하다.

4. 직접 관련성이 높은 3건의 적용 설계

4.1 AgentOnto → 제조·투자엔지니어링 온톨로지

적용 단계

  1. 문서·표·DB를 E: 엔터티/관계, M: 계산·판정 규칙, G: 원문·열·SPARQL/SQL 매핑으로 분리한다.
  2. 모든 항목에 출처 위치, 문서 버전, 확인 상태를 붙인다.
  3. 분석 요청을 실행 / 추가질문 / 지원 불가로 먼저 분류한다.
  4. 계획이 온톨로지의 정의·단위·적용조건과 일치할 때만 계산한다.
  5. 온톨로지 변경마다 correction test와 retention test를 함께 수행한다.
필요 자료
현재 Transformer 추출기, Protégé OWL, 설계문서·견적표, gold competency questions. AgentOnto 구현은 공개 확인되지 않아 자체 재구현이 필요하다.
최소 검증 실험
60개 요청—30 실행 가능, 15 모호, 15 지원 불가. 직접 LLM/Transformer, 온톨로지를 프롬프트에만 제공, 계획-검사-실행 방식을 비교한다. 지표는 action accuracy, result exact match, silent semantic error, SHACL 위반, 비용·지연이다.
4.2 HeritageKGBench → 문장→온톨로지 트리플

적용 단계

  1. 최소 100개 산업 문장에서 약 300–500개 gold triples를 전문가가 작성한다.
  2. 다음 세 조건을 비교한다: 단일 추출, 단계별 agent+gate, 단일 추출+사후 SHACL repair.
  3. 단순 SPO 외에 사건, 시간, 측정값·단위, 주장자, 근거 문서까지 재구체화한다.
  4. 단계별 gate가 빈 그래프를 만드는지 기록한다.
최소 지표
micro/macro triple F1, Turtle parseability, SHACL validity, event-mediation completeness, provenance accuracy, near-empty graph rate.
핵심 가설
사후 SHACL은 형식·국소 제약은 복구하지만, 처음부터 누락된 사건이나 관계는 복원하지 못한다. 이는 원 논문의 강한 부정적 결과에서 도출한 연결 추론이다.
4.3 PerMIT → 멀티에이전트 온톨로지 신뢰 계층

적용 단계

  1. agent가 추출한 트리플을 곧바로 trusted KG에 넣지 않고 quarantine graph에 저장한다.
  2. gate에는 정확한 트리플, 근거 문장, 문서·페이지, 생성 agent, 예정된 사용 범위를 표시한다.
  3. 승인된 내용만 trusted named graph로 승격하고 서명된 verdict를 남긴다.
  4. 다른 agent는 내용 자체가 아니라 승인된 handle을 통해서만 민감 작업에 사용한다.
  5. 반복적으로 승인되는 동일 내용은 범위가 같은 경우에만 재사용한다.
최소 실험
정상 20건+간접 프롬프트 주입 20건을 2개 세션에 걸쳐 실행한다. raw shared memory, prompt filter, gated memory를 비교해 ASR, benign FPR, task completion, 사람 검토 횟수, 오래된 승인 재사용 오류를 측정한다.

6. 한국어 미니 튜토리얼: NIKG를 Protégé와 검증 스크립트로 살펴보기

실행 상태. 아래 절차는 원문과 README를 대조해 작성했지만 이번 브리핑 작성 환경에서는 nuScenes 데이터를 내려받아 실제 실행하지 않았다.

논문

Python 3.11 환경, OWL/Turtle, 생성기, 통계·일관성 검사 및 사전 생성 사례가 포함된다. 코드 MIT, 생성 그래프와 이미지는 nuScenes의 CC BY-NC-SA 조건을 따른다.

개념

NIKG는 다음 두 층을 한 Turtle 파일에 합친다.

  • TBox: SceneParticipant, SpatialZone, TTCRiskLevel 등의 클래스·속성·열거값
  • ABox: 각 장면·프레임·참여자와 motionTowardEgo, spatialConfiguration, ttcRisk 사실
논문에서 수행한 “semantic consistency”는 OWL reasoner의 자동 분류 결과가 아니라 RDF 트리플을 스캔해 세 가지 implication의 통과율을 계산한 것이다.

검증 질문과 정답 기준

1. 왜 첫 등장 participant에는 motionTowardEgo가 없을 수 있는가?

정답: 이전 keyframe과의 거리 변화가 필요하기 때문이다.

2. ttcRisk=High인데 forward zone이 아닌 사례는 모두 그래프 오류인가?

정답: 아니다. TTC가 경로가 아닌 line-of-sight 평면거리로 계산되어 측면·후방 접근이 포함될 수 있다.

3. SHACL·일관성 검사 통과는 의도예측 모델의 정확도를 입증하는가?

정답: 아니다. 스키마·관계의 내부 일관성과 downstream predictive validity는 다른 평가다.

4. Protégé reasoner가 99.9% 통과율을 계산해 주는가?

정답: 논문의 수치는 제공 평가 스크립트의 implication 검사 결과다. OWL reasoner 결과와 혼동하면 안 된다.

평가상 주의점

  • nuScenes mini에만 맞춘 수치이며 다른 데이터셋 일반화가 검증되지 않았다.
  • 50m 공간 범위, 0.5m 정지 임계값 등은 코드에 고정되어 있다.
  • 실제 의도예측 성능이나 인과적 안전 개선은 평가하지 않았다.
  • 사용자의 산업문서 연구로 이전할 때는 motion/TTC 대신 문서상태/설계성숙도/비용위험을 관계로 바꾸고, 각 관계의 emission condition과 미기재 사유를 명시해야 한다.

7. 향후 제공 작업을 더 구체화하는 권장 방식

다음 주부터는 결과물을 다음처럼 고정하면 연구용으로 더 유용하다.

  • 관련성을 A: 즉시 실험 가능 / B: 방법 전이 가능 / C: 배경자료로 등급화
  • “새 논문”과 “실질 개정판”을 분리하고 개정판은 무엇이 바뀌었는지만 보고
  • 코드·데이터 상태를 공개/부분공개/요청필요/미공개로 명시
  • 결과값마다 저자 보고값, 독립 재현값, 본 브리핑 미실행을 구별
  • 교육 설계는 논문별로 학습목표 하나, 실습 하나, 평가 문항 하나만 유지
  • 사용자 연구 연결은 매주 최소 한 건씩 다음 중 하나로 끝내기:
    • Protégé에서 바로 시험할 competency question
    • 문장→논리/트리플 gold 사례
    • 멀티에이전트 공격·신뢰 최소 실험
    • AACE/엔지니어링 문서용 온톨로지 변경 제안
