우선도 AAPOLO: Automatic Prompt Optimization for Ontology Learning

Mai 외9월 28일ISWC 2026 Posters & Demos 채택
방법·평가·결과
12개 공개 온톨로지에서 다중 에이전트가 텍스트–OWL 쌍을 생성하고, Greedy·Autoregressive 학습기의 프롬프트를 GEPA로 최적화한다. DOID·Plant Ontology를 보류 평가에 사용했다. Qwen3.5-27B AR의 DOID axiom precision은 0.569→0.838로 증가했다. 엔터티와 공리의 precision/recall을 분리하고, 공리 평가는 reasoner 기반 함의를 사용한다.
핵심 한계

연결 연구 연결점
사용자의 문장→논리 표현→트리플을 엔터티 추출·공리 생성·일관성 검사로 분리하고, 정확 문자열 일치 대신 reasoner 기반 entailment 평가를 추가할 수 있다.

APOLO v1 원문 (arXiv)

3. 직접 적용 우선순위 3건

① APOLO — 현재 연구에 가장 직접적

적용 위치

문장
→ 논리 표현
→ 후보 클래스·개체·공리
→ 파싱 및 일관성 검사
→ 추론기 기반 함의 평가
→ 트리플/OWL 저장

현재 exact match 또는 트리플 단위 F1만 사용하고 있다면 다음을 추가할 수 있다.

  • Entity precision/recall
  • Axiom precision: 생성 공리가 정답 온톨로지에서 함의되는 비율
  • Axiom recall: 정답 공리가 생성 온톨로지에서 함의되는 비율
  • Parse success rate
  • Consistency rate
  • Redundant axiom rate
  • 원문 인용과 공리 간 evidence alignment
최소 검증 실험
  • 데이터: 기존 Petrucci 2,000건에서 train/validation/test를 문서 또는 온톨로지 단위로 분리
  • 비교군:
    1. 기존 Transformer→논리→트리플
    2. 기존 모델+수동 프롬프트
    3. 기존 모델+자동 최적화 프롬프트
    4. autoregressive ontology context 추가
  • 필수 조건: 같은 test set을 프롬프트 최적화 과정에서 반복 조회하지 않는다.
  • 권장 통계: 세 개 이상 seed, 문서 단위 bootstrap CI, 도메인별 분리 결과
  • 실험상 핵심: APOLO의 평가에서 빠진 중복 공리율과 과잉 생성률을 반드시 추가한다.

에이전트 출력에 다음 최소 메타데이터를 붙이는 방식이 적합하다.

claim_id
source_agent
source_sentence
formal_axiom
authority = hard | soft
priority
validation_status
conflicts_with
relaxation_history
최소 실험
  • 같은 개념에 대해 상충하는 30~50개 제약 쌍 구성
  • 조건:
    • 출처 구분 없음
    • hard/soft 구분만 적용
    • 출처+우선순위+OWL 충돌 검출 적용
  • 지표:
    • 미검출 모순 수
    • 잘못 완화한 hard constraint 비율
    • 해결 불가능한 경우의 abstention 정확도
    • 설명에서 실제 충돌 공리를 정확히 지목한 비율

③ Safety of Latent Communication — 시스템 수준 신뢰 평가

사용자 연구에서 에이전트 A가 만든 논리 표현을 에이전트 B가 검증한다면, 전달 형식별 성능을 비교할 수 있다.

  • 원문 자연어
  • 정형 JSON
  • 논리식
  • 트리플
  • 임베딩 또는 압축 표현

각 조건에서 의미 보존율, 모순 탐지율, 공격 명령 전달률, 최종 트리플 F1을 함께 측정해야 한다. 개별 에이전트의 정확도가 같아도 통신 변환기가 오류나 공격 성공률을 증가시킬 수 있다는 것이 이번 연구의 핵심 경고다.

4. 교육공학적 적용안

주의 아래는 논문에서 입증된 교육 효과가 아니라, 논문 결과를 근거로 구성한 제안 수업 설계다.
요소설계
대상Python·기초 ML을 알고 지식그래프 또는 OWL을 처음 적용하는 연구자·산업 AI 학습자
사전 지식클래스·개체·관계, precision/recall, train/test 분리
학습목표 1자연어 문장에서 클래스·개체·공리를 구분해 작성한다
학습목표 2문자열이 다른 두 공리가 논리적으로 동치 또는 함의 관계인지 reasoner 기준으로 판정한다
학습목표 3파싱 성공, 일관성, 엔터티 정확도, 공리 정확도를 분리해 보고한다
학습목표 4에이전트 결과·평가자 결과·인간 검수 결과가 불일치하는 사례를 분류한다
실습동일 텍스트에 Greedy 추출과 이전 공리를 참조하는 AR 추출을 적용하고, 누락·과잉·모순을 비교
평가공리 작성 30%, 오류 분류 20%, 지표 계산 20%, 테스트 누출 방지 설계 20%, 한계 기술 10%

예상 오개념과 피드백

“문법적으로 유효한 OWL이면 올바른 온톨로지다”

→ 파싱 가능성, 논리적 일관성, 원문 충실성은 별도 조건임을 반례로 확인한다.

“생성 공리가 많을수록 recall이 높으므로 좋은 결과다”

→ precision, 중복 공리율, 과잉 생성률을 함께 계산한다.

“reasoner가 모순을 찾지 못하면 원문 의미를 보존했다”

→ reasoner는 주어진 공리들의 관계를 검사할 뿐, 자연어–공리 정렬 오류를 자동으로 보장하지 않는다.

“LLM 평가 점수가 높으면 인간 평가도 대체된다”

→ PADMÉ에서도 인간 검증은 별도로 수행됐고, 보고된 일치율은 85%이지 100%가 아니다.

5. 정보 기반 미니 튜토리얼

문자열 일치 대신 추론기 기준으로 온톨로지 출력을 평가하기

형태: 비실행형 개념·설계 튜토리얼. APOLO 원문과 수식·실험표는 공개되어 있지만, 이번 확인 범위에서는 완성된 공식 재현 저장소를 확인하지 못했다. 따라서 아래 절차는 실행 검증된 APOLO 복제 코드가 아니다.

준비물

  • APOLO v1 원문
  • Protégé
  • HermiT 또는 ELK reasoner
  • 두 개의 OWL 파일:
    • gold.owl: 전문가 정답
    • predicted.owl: 모델 생성 결과
  • 원문 문장과 생성 공리를 연결한 표

예제

원문:

모든 전기 모터는 설비이며, Motor-01은 전기 모터이다.

정답 공리

ElectricMotor SubClassOf Equipment
Motor01 Type ElectricMotor

모델 출력 A

ElectricMotor SubClassOf Equipment
Motor01 Type ElectricMotor

모델 출력 B

Motor01 Type Equipment

모델 출력 C

ElectricMotor DisjointWith Equipment
Motor01 Type ElectricMotor

단계별 평가

  1. 파싱 검사
    각 출력이 OWL 문법으로 로드되는지 확인한다. 로드되지 않으면 APOLO 방식에서는 해당 출력 점수를 0으로 처리한다.
  2. 일관성 검사
    Reasoner를 실행한다. 출력 C는 ElectricMotor ⊑ Equipment라는 정답 구조와 함께 사용할 경우 배타 공리와 충돌할 수 있다.
  3. 엔터티 평가
    ElectricMotor, Equipment, Motor01의 추출 여부를 precision·recall로 계산한다.
  4. 공리 precision 평가
    모델 공리 각각이 gold.owl에서 함의되는지 검사한다.
    • A의 두 공리: 모두 함의됨
    • B의 Motor01 Type Equipment: 정답에 명시되지는 않았지만 두 정답 공리로부터 함의됨
    • 따라서 B를 단순 문자열 불일치만으로 오답 처리하면 안 된다.
  5. 공리 recall 평가
    정답 공리 각각이 predicted.owl에서 함의되는지 검사한다.
    • B는 Motor01 Type Equipment만 포함하므로 원래의 클래스 계층과 직접 타입 공리를 복구하지 못한다.
    • 최종 사실 하나를 맞혔지만 온톨로지 구조의 재현성은 낮다.
  6. 원문 충실성 검사
    각 생성 공리에 근거 문장을 연결한다. Reasoner 통과 여부와 별개로, 원문이 실제로 해당 공리를 지지하는지 사람이 확인한다.

기대 출력

출력파싱일관성함의 기반 precision구조 recall판정
A통과통과높음높음적합
B통과통과높을 수 있음낮음불완전
C통과실패 가능낮음판정 전 수정 필요모순

검증 문항

1. Motor01 Type Equipment가 정답 파일에 문자열로 없으면 무조건 오답인가?
정답: 아니다. 정답 온톨로지에서 논리적으로 함의되는지 확인해야 한다.
2. 일관성 있는 생성 온톨로지는 원문을 충실히 표현했는가?
정답: 보장되지 않는다. 잘못된 공리끼리도 일관적일 수 있다.
3. axiom recall만 최대화하면 어떤 문제가 발생하는가?
정답: 불필요하거나 근거 없는 공리를 대량 생성해 recall을 높일 수 있으므로 precision·중복률·과잉 생성률을 같이 봐야 한다.

평가상 주의

  • reasoner 종류와 지원하는 OWL 프로파일을 고정해야 한다.
  • 동치 공리, 추이 관계, 복수의 유효한 형식화를 고려해야 한다.
  • 개발 과정에서 같은 test ontology를 반복 조회하면 프롬프트가 테스트셋에 맞춰질 수 있다.
  • APOLO 결과는 단일 실행이므로, 적용 연구에서는 seed 반복과 신뢰구간 보고가 필요하다.
  • 바이오·식물 온톨로지에서의 결과를 사용자 도메인으로 직접 일반화할 수 없다. APOLO 연구 자체도 PO에서 상대적으로 낮은 공리 성능을 보였다.
