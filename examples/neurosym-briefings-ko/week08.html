OGDA — Ontology-Grounded Data Agents for Reliable Analysis over Heterogeneous Data Lakes

데이터 에이전트·온톨로지미심사 프리프린트2026-11-09 v1
서지
사실 Boyi Zhang 외, HKUST/HKBU; 원문 · 코드
기여·방법
사실 원시 파일에서 스키마·개념·관계를 제안하고 독립 검증기가 이를 검사한다. 분석 단계에서는 온톨로지 기반 task graph가 에이전트가 읽을 수 있는 파일과 실행 순서를 제한한다.
연구 연결점
연결 문장→논리→트리플뿐 아니라 “어떤 원문·파일에서 그 트리플과 계산값을 얻을 수 있는가”를 task graph로 통제하는 층을 추가할 수 있다.
평가·결과·한계
평가 설계
사실 KramaBench 104과제·약 1,700파일·24개 소스·6개 도메인과 DiscoveryBench 239과제. Smolagents, Reflexion, DS-STAR, Data Interpreter, DatawiseAgent와 비교하고 답 정확도, 파이프라인 점수, HMS·ctxF1·varF1을 측정했다.
결과
저자 세 백본에서 최강 기준선 대비 Krama 답 점수가 각각 10.82, 3.30, 10.46점 높았다. grounding agent 제거 시 73.00→60.94로 하락했다.
한계
사실 OWL/DL 추론기가 아니라 파일·스키마 수준 온톨지다. LLM 평가기 의존, 온톨로지 구축비용, 특정 데이터 분석 벤치마크라는 제약이 있다.

TIGA — Controlled Knowledge Engineering for Taxonomy Induction

Taxonomy 유도투고 중·현재 미심사2026-11-10 v1
서지
사실 Jonas Limniatis 외, Lufthansa Technik 등; Knowledge-Based Systems 투고 중; 원문 · 코드
기여·방법
사실 LLM이 자유 텍스트로 계층을 출력하는 대신 제한된 편집 도구, 명시적 taxonomy 상태, 동적 정책, 선택적 reviewer를 이용한다.
연구 연결점
연결 Transformer 추출 결과를 Protégé에 바로 넣기 전에, 제한된 add/move/delete 연산과 검토 정책으로 taxonomy를 조립하는 중간 계층으로 적합하다.
평가·결과·한계
평가 설계
사실 WordNet 761개 하위 트리의 533/114/114 분할, DBLP 5개 taxonomy, TExEval-2 18개 taxonomy, GProd. GPT-5.4-mini와 Gemma4-31b, HF·Chain-of-Layer 기준선, 5회 반복. edge/ancestor P·R·F1, coverage, extraneous entities, 트리 유효성 및 비용을 측정했다.
결과
저자 Gemma 조건에서 ancestor/edge F1이 WordNet 85.82/66.86, DBLP 75.60/55.30, TExEval-2 82.60/64.60, GProd 85.20/71.20. 8개 설정 중 7개에서 최고였지만, 일부 조건에서는 reviewer가 오히려 성능을 낮췄다.
한계
사실 단일 부모의 rooted tree만 다룬다. 다중 상속, 객체속성, 공리, OWL 일관성은 평가하지 않았고 호출비용이 크다.

로봇 URDF→OWLAAAI Fall Symposium 2026 proceedings 수록2026-11-10 v1
서지
사실 Bastien Dussard, Aurélie Clodic, Guillaume Sarthou; AAAI Fall Symposium 2026 proceedings 수록; 원문 · 코드
기여·방법
사실 URDF를 그래프로 바꾼 뒤, 로컬 gpt-oss:20b가 고정된 OWL TBox에 맞춰 ABox를 생성한다. 그래프 정리, bottom-up Tree Track, top-down Chain Track, 구문 검증을 사용한다.
연구 연결점
연결 URDF 대신 문장·절·개체를 노드로 한 문서 그래프를 입력하면 사용자 파이프라인에 가깝다. 다만 HermiT/SHACL 검증과 원문 span provenance를 반드시 보강해야 한다.
평가·결과·한계
평가 설계
사실 Solo, RB-VOGUI+, PR2, iCub, Ingenuity 등 5개 로봇. 추출된 개체·개념을 질적으로 분석했으며 표준 정확도 기준선이나 train/test 분할은 없다.
결과
저자 최대 134개 링크의 iCub를 처리했다. 150개 촉각 셀을 그대로 포함하면 문맥 열화와 환각이 나타났고, 필터링 후 개선됐다.
한계
사실 로봇 5종·TBox 1개, 식별자 의미에 의존하는 사례연구다. OWL reasoner 기반 일관성 검사는 향후 과제로 남았다.

ProVeST — Progressive Semantic Verification for Multi-Hop KGQA

KGQA·검증심사 논문2026-11-09
서지
사실 Zicheng Zuo 외; Information 17(11):1119; DOI 10.3390/info17111119
방법
사실 질문을 하위 질문으로 분해하고, 그래프 후보를 점수화한 뒤 LLM이 개체와 경로 문맥을 검증한다. 검증된 개체만 다음 hop의 상태에 들어간다.
연구 연결점
연결 추출된 논리 표현이나 트리플이 검증되기 전에는 다음 추론 단계의 상태로 승격하지 않는 설계에 활용할 수 있다.
평가·결과·한계
평가 설계
사실 WebQSP 2,848/250/1,639, CWQ 27,639/3,519/3,531; Hit@1·F1; 3개 LLM 백본.
결과
저자 GPT-4 조건에서 WebQSP .803/.741, CWQ .619/.573. 계획 모듈 제거 시 CWQ Hit@1/F1이 .161/.160 하락했다.
한계
사실 LLM 검증은 형식 증명이 아니며 후보 수가 제한된다. 첫-hop 상태 분석도 35문항에 그친다.

서지
사실 S. M. Rayeed, Charles V. Stewart, Yao Ma; 원문
방법
사실 문서가 구체적 질병 대신 상위 질병군만 제공하는 “resolvable insufficiency”를 분석하고, 온톨로지의 하위 후보 목록으로 복구를 시도한다.
연구 연결점
연결 상위 클래스 근거만으로 특정 instance 트리플을 확정하지 않도록 class-supported와 instance-supported 상태를 분리할 필요가 있다.
평가·결과·한계
평가·결과
저자 PrimeKG에서 상위군 정보는 abstention을 13.8%p 줄였지만 추측의 약 절반이 틀렸다. 정답을 포함한 후보 목록은 98.5% 생성했지만 end-to-end 복구는 10.0%→26.8%에 머물렀다. GloBI에서도 재현했다.
한계
사실 온톨로지는 후보를 열거할 뿐 올바른 하위 개체를 결정해주지 않는다.

4. 사용자 연구에 대한 우선 적용안 3건

A. OGDA 기반 “근거 제한형 온톨로지 추출”

  1. 프로젝트 문서·CSV·DB의 스키마와 개념을 제안하되 모든 edge에 source ID를 붙인다.
  2. 별도 검증기가 데이터 profiling 및 competency question으로 제안을 승인한다.
  3. 질의를 source selection → extraction → logic conversion → reasoner → answer task graph로 컴파일한다.
  4. 각 단계는 task graph가 허용한 파일만 읽게 한다.
필요 자료
OGDA 코드, 과거 프로젝트 3–5개, 60–100개 질의, 정답 파일·트리플 표본.
최소 실험
프로젝트 단위 분할로 60개 질의를 사용해 ① 직접 ReAct, ② read-only ontology, ③ 강제 task graph를 비교한다. 답 정확도, 필요 파일 precision/recall, 허가되지 않은 파일 접근, triple F1, 비용을 측정한다.

B. URDF2Ontology를 문장→OWL 파이프라인으로 변환

  1. 문서를 절–문장–개체 그래프로 변환한다.
  2. 관련 소그래프와 고정 TBox만 Transformer/LLM에 제공한다.
  3. 모델은 class assertion·object property·data property 후보를 생성한다.
  4. SHACL과 HermiT가 구문·domain/range·불일치·unsatisfiable class를 검사한다.
  5. 실패한 후보는 자동 확정하지 않고 원문 span과 함께 보류한다.
최소 실험
문서 독립 분할의 수작업 표본 200문장으로 ① 단일 프롬프트, ② schema-constrained, ③ 소그래프+reasoner를 비교한다. entity/triple F1, 논리적 유효률, unsatisfiable 수, competency-question 정확도와 비용을 측정한다.

C. ActiveSecHarness 기반 멀티에이전트 권한 경계

  • raw-read → propose → calculate → ontology-write → approve/export 권한을 분리한다.
  • 데이터에 trusted/sanitized/derived/untrusted × public/sensitive 라벨을 전파한다.
  • LLM judge는 조언만 하고, DB·파일·Protégé 수정과 외부 전송 직전에 결정적 guard를 둔다.
  • 에이전트 위임·권한 철회·간접 prompt injection의 전체 trajectory를 기록한다.
최소 실험
정상 작업 100개, 공격 100개, 다단계 공격 20개에서 prompt-only, LLM judge, regex, lattice guard, hybrid를 비교한다. 공격차단률, 정상 오탐률, 철회 후 write 수, 민감정보 누출, 지연시간을 측정한다.

핵심 개념

TIGA의 핵심은 LLM에게 전체 taxonomy 문자열을 한 번에 쓰게 하지 않는 것이다.

  1. 현재 taxonomy와 미배치 개체를 상태로 유지한다.
  2. 모델은 허용된 편집 도구만 호출한다.
  3. 정책은 남은 오류나 상태에 따라 갱신된다.
  4. reviewer를 선택적으로 사용한다.
  5. 최종 결과를 구조 유효성과 의미적 F1로 따로 평가한다.

준비와 데이터 검증

git clone https://github.com/bschaarmann/TIGA.git
cd TIGA
uv sync --locked

uv run tiga prepare-data --config configs/reproduction.toml
uv run tiga validate-data --config configs/reproduction.toml

예상되는 것은 각 benchmark 원자료가 준비되고, 레코드 스키마·필수 필드·개체 집합을 검사한 결과다. 정확한 로그 문자열은 환경과 저장소 버전에 따라 달라질 수 있다.

최소 smoke test

configs/reproduction.toml을 configs/local.toml로 복사하고 다음과 같은 최소 조건으로 줄인다.

prompt_variants = ["no_policy"]
reviewer = false
repetitions = 1
record_limit = 1

그다음 실행한다.

uv run tiga run --config configs/local.toml

API 키와 모델 이름은 저장소의 provider 설정에 맞춰 별도로 지정해야 한다. 실행이 성공하면 한 레코드에 대한 모델 호출 기록, taxonomy 상태 변화, 최종 예측 및 평가용 산출물이 생성되어야 한다. 경로나 파일명은 선택한 config와 저장소 버전을 기준으로 확인한다.

직접 검증할 조건

최종 taxonomy T=(V,E)에 대해 다음을 검사한다.

  1. 모든 기대 개체가 정확히 한 번 존재하는가?
  2. 허용되지 않은 개체가 추가되지 않았는가?
  3. root의 부모는 0개이고 다른 노드의 부모는 정확히 1개인가?
  4. 모든 노드가 root에서 도달 가능한가?
  5. cycle이 없는가?
  6. 구조가 유효하더라도 gold parent와 의미적으로 일치하는가?
  7. direct-edge F1과 ancestor F1이 왜 다른가?
예를 들어 정답이 동물→포유류→개인데 모델이 동물→개→포유류를 만들면 rooted tree로서는 유효하지만 의미적으로 틀리다.

확인 문제와 정답 기준

1. Reviewer를 붙이면 항상 더 정확한가?
아니오. TExEval-2 일부 조건에서는 성능이 하락했다.
2. Ancestor F1이 edge F1보다 높을 수 있는 이유는?
직접 부모를 틀려도 더 먼 상위–하위 관계 일부는 유지될 수 있기 때문이다.
3. 이 결과를 OWL 온톨로지 생성 성능으로 바로 해석할 수 있는가?
아니오. 실험은 단일 부모 taxonomy이며 객체속성·제약·다중 상속·논리적 충족가능성을 평가하지 않는다.
4. 사용자 연구로 옮길 때 추가할 검증은?
원문 span 추적, relation/triple F1, SHACL, HermiT 일관성, competency question, 문서 독립 분할이 필요하다.

평가상 주의점

  • 모델과 provider 버전이 바뀌면 결과가 달라질 수 있다.
  • 같은 개체명이 사전학습에 존재할 수 있으므로 무작위 분할보다 도메인·프로젝트 독립 분할이 낫다.
  • 완전한 rooted tree 생성률과 의미 정확도를 합쳐 보고하면 실패 원인이 가려진다.
  • reviewer 호출비용과 수정 횟수를 성능과 함께 보고해야 한다.
  • 공개 benchmark의 원 라이선스도 별도로 확인해야 한다.

7. 이번 주의 결론

이번 주의 공통 흐름은 “신경 모델이 더 잘 추론하도록 만드는 것”보다 신경 모델의 출력을 어떤 상태·도구·근거·권한 경계 안에서만 사용할 것인가에 있다.

사용자 연구에는 다음 우선순위가 가장 타당하다.

  1. 문장→논리/트리플마다 원문 provenance를 보존한다.
  2. 검증된 트리플만 온톨로지와 다음 추론 단계에 승격한다.
  3. Protégé/HermiT의 일관성과 원문 fidelity를 별도 평가한다.
  4. 멀티에이전트 agreement가 아니라 거절 표본의 false negative도 감사한다.
  5. 온톨로지·memory·규칙 변경은 반증 및 회귀 검사를 통과한 뒤 반영한다.
