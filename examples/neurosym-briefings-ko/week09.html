1) CPAM-LLM: Automated Data-to-Model Transformation for Constraint Programming

동료심사 완료오픈 액세스2026-11-19 · Nature Communications
저자·기관
Zhengqi Shi, Jin Huang, Xinyu Li 외; Huazhong University of Science and Technology
DOI
10.1038/s41467-026-78715-2
기여·방법 사실
자연어 최적화 문제를 실행 가능한 constraint-programming 모델로 변환한다. formal concept analysis 기반 RAG, 구조 검증, chaos-mapping 데이터 증강, 변화한 요구사항에 대한 동적 제약 갱신을 결합한다.
평가 사실
DNA 서열 설계, 재구성형 에너지 저장장치, 무인차량 물류 등을 포함한 5개 시나리오. 공개 색인에서 정확한 분할·기준선·수치표는 확보하지 못했다.
결과 저자
다섯 도메인에서 데이터→형식모델 파이프라인과 요구사항 변화에 대한 적응 가능성을 보고했다.
한계
접근 가능한 초록만으로는 모델별 성능, 실행 성공률, solver-equivalence를 검증할 수 없다. 재현 코드 링크도 확인되지 않았다.
연결 연결
사용자 연구의 문장 → 논리 표현을 단순 문자열 exact match 대신 실행 가능성·충족가능성·정답 동치성으로 평가하는 근거가 된다.

2) NeSySy: Synthetic Neurosymbolic Task Generation with Controlled Constraint Complexity

arXiv 미심사TACAS 2027 artifact2026-11-14 v1
저자
Mykhailo Buleshnyi, Zsolt Zombori, Michael Benedikt
심사
arXiv 자체는 미심사. Zenodo에서 TACAS 2027 artifact로 명시
원문·자료
arXiv · Artifact v1.0
기여·방법
CNFgen·Z3가 SAT/SMT 제약을 만들고, RC2 MaxSAT 또는 Z3 OMT가 비일관 출력의 최소 수정을 계산한다. Boolean·실수 제약, 입력 의존 제약, distant supervision을 지원한다.
평가 설계
기본 3,000개 generator 학습점, 생성 데이터 5,000개, 70/10/20 분할, 데이터 seed 5개×학습 seed 5개. Base, BaseSolver, DRL, CCN+, BaseSeq, DeepProbLog을 accuracy·violation rate·MAE로 비교한다. supervision-size 실험은 총 20,000개와 학습표본 80–16,000개를 사용했다.
결과
solver 기반 최소 수정이 복잡한 조건에서도 안정적이었다. fixing 방식은 filtering보다 다양한 동시에 어려운 데이터를 만들었고, hidden 1,024 조건의 Base accuracy가 filtering .8515, fixing .5821이었다.
한계
실제 문서나 온톨로지가 아닌 합성 제약 중심이다. 정수·시계열·표본 간 제약은 미지원이며 비교한 신경·기호 시스템도 제한적이다.
연결 연결
Transformer가 출력한 논리식의 난이도와 위반율을 독립적으로 통제하는 회귀시험 생성기로 사용할 수 있다.

3) GRASP: Query-Adaptive Graph Retrieval with Path-Sufficiency Verification

미심사 프리프린트2026-11-14 v1
저자
Rui Xu, Le Wang, Tianyue Wang
원문
arXiv
방법
query–edge cross-attention, 적응형 stopping gate, 경로 충분성 분류기, 불충분한 경로의 국소 재검색을 결합한다.
평가
RiTeK 3,500/1,500/100, MedKGent-KG 672/288/100, PMC 3,500/1,500/100. MedKGent는 15.6만 개체·297만 트리플이다. BFS-2/3, G-Retriever, GNN-RAG, MINERVA와 Hits@1/3, MRR, Path Recall, unsupported-claim rate로 비교하고 5 seed와 10,000회 bootstrap을 적용했다.
결과
GRASP의 Hits@1은 RiTeK 85.2, MedKGent 76.8로 MINERVA보다 10.0·10.4%p 높았다. unsupported-claim rate는 세 데이터셋에서 8.9–13.2%p 감소했다. 다만 국소 재검색의 전체 정확경로 복구율은 38.5%였다.
한계
생의학 도메인, 테스트 각 100문항으로 작다. NLI 기반 unsupported 판정은 인간 검증 F1이 클래스별 약 .70–.86이며 형식 증명이 아니다.
연결 연결
Protégé KG에서 검색된 경로가 질문에 충분한지 판단한 뒤, 충분한 경로만 Transformer 답변에 제공하는 gate로 적용할 수 있다.

4) ACaM: Automated Capability Modeling for Agentic AI Security

미심사 프리프린트2026-11-17 v1
저자·기관
Monika Santra 외; Penn State, IBM Research
원문
arXiv
방법
agent/tool Python 코드를 정적 분석해 Agent Capability Property Graph를 만든다. 정적 분석이 확정한 사실은 LLM이 낮추거나 덮어쓸 수 없고, LLM은 코드 구조만으로 결정할 수 없는 의미 판정만 보충한다.
평가
실제 agent 43개, 그중 MAS 9개. 수작업 주석 24개에서 capability macro-F1, 삽입된 위협 경로에서 chain reconstruction, 실제 코드에서 PoC를 평가했다.
결과
capability macro-F1 98.3%, 위협경로 점수 .980으로 최강 LLM-only 기준선 .903보다 약 8%p 높았다. 123개 code-execution/credential-exposure 경로와 약 1,800개 중·고위험 경로를 찾고 10개를 PoC로 확인했다.
한계
Python white-box 분석에 한정되고, 동적 코드·reflection·원격 black-box 도구는 범위 밖이다. worst-case taint 전파로 오탐이 발생할 수 있다. 코드 공개 링크는 원문에서 확인하지 못했다.
연결 연결
RE:CHARGE의 Calculator·Policy Engine·DB tool이 “설명상 무엇을 하는가”가 아니라 코드상 무엇에 접근·기록·전송할 수 있는가를 graph로 사전 감사하는 방식이다.

원문
arXiv
방법

검증과 passage 우선권을 한 prompt에 넣으면 pre-cutoff 정답을 거짓 passage로 대체하는 현상이 다섯 모델 모두에서 증가했다. adversarial-aware prompt는 밀려난 정답의 82.5–98.9%를 복원했다.
한계
사실 QA 중심이며 KG·온톨로지 추론을 직접 수행하지 않는다. 모델 내부 지식이 맞는 경우와 최신 외부 근거가 맞는 경우의 정책이 다르다.
연결 연결
“검색 문서를 무조건 우선하라”가 아니라 승인일·revision·source authority에 따라 외부 근거와 기존 온톨로지의 우선순위를 결정해야 한다.

B. GRASP → 온톨로지 경로 충분성 Gate

  3. 매 hop에서 계속 탐색할지 중단할지 판정한다.
  4. 완성 경로가 질문의 모든 조건을 지지하는지 검사한다.
  5. 불충분하면 가장 약한 hop으로 돌아가 다른 relation을 선택한다.

중요 주의점. GRASP의 NLI 검증을 OWL entailment와 동일시해서는 안 된다. 명시적 공리는 HermiT가, 문장 근거의 의미적 지지는 NLI/LLM이 담당하도록 분리한다.

실행 검증하지 않음. 이번 조사에서는 파일 구조와 공개 메타데이터까지만 확인했으며 설치·실행하지 않았다. 아래는 비실행 재현 절차다.

개념

Boolean 출력 O1, O2, O3에 다음 제약이 있다고 하자.

(¬O1 ∨ O2 ∨ O3) ∧ (O1 ∨ ¬O2 ∨ O3)

이 식은 100, 010을 허용하지 않는다. 일반 신경망이 100을 예측하면 다음 두 방식이 가능하다.

Filtering

해당 표본을 버리고 새 표본을 뽑는다.

Fixing

MaxSAT으로 최소 비트만 바꿔 101과 같은 가장 가까운 만족 해를 만든다.

Filtering은 원래 생성분포를 덜 왜곡하지만 다양성이 낮아질 수 있고, fixing은 입력을 보존하지만 제약 경계에 표본이 몰릴 수 있다.

준비

  • Linux 또는 WSL 권장
  • Python 환경
  • 전체 distant-supervision 실험은 GPU가 유리하지만 기본·smoke test는 CPU 대상
  • unzip, shell
  • 전체 artifact 사용 전 README.md, install.sh를 먼저 검토할 것

예상해야 할 출력 특성

정확한 stdout 문자열은 실행하지 않아 제시하지 않는다. 대신 다음 조건을 확인해야 한다.
  1. 생성된 논리식이 SAT/SMT solver에서 satisfiable이다.
  2. 생성 데이터의 모든 (input, output) 쌍이 제약을 만족한다.
  3. fixing 전후 출력의 Hamming 또는 L1 거리가 기록 가능하다.
  4. 모델 결과에서 accuracy와 violation rate가 별도로 계산된다.
  5. solver correction을 적용한 결과의 violation rate는 0이어야 한다.
  6. 같은 seed에서 생성 설정과 데이터가 재현되어야 한다.

검증 질문·정답 기준

1. BaseSolver accuracy가 항상 Base보다 높아야 하는가?
아니오. solver는 제약 만족을 보장하지만 여러 만족 해 중 gold와 다른 해를 선택할 수 있다.
2. Violation rate 0이면 의미적으로 정확한가?
아니오. 제약이 불완전하거나 잘못되면 틀린 결과도 제약을 만족한다.
3. Filtering과 fixing 중 어느 것이 항상 우수한가?
항상 우수한 방법은 없다. filtering은 선택편향, fixing은 분포왜곡을 일으킬 수 있다.
4. Protégé 연구에 그대로 적용할 수 있는가?
직접 적용은 어렵다. CNF/QF-LRA 대신 OWL 공리, SHACL shape, competency question을 생성·검사하는 adapter가 필요하다.

평가상 주의점

  • 학습 데이터와 테스트 데이터가 동일 제약 생성 seed를 공유하면 일반화가 과대평가될 수 있다.
  • accuracy와 constraint satisfaction을 하나의 점수로 합치지 않는다.
  • 수정 후 출력만 보고하면 원 모델의 위반 정도가 숨겨진다.
  • 실제 온톨로지에서는 “제약 만족” 외에 원문 충실성, domain/range, 출처, revision, open-world assumption을 별도로 평가해야 한다.

6. 이번 주 핵심 결론

  1. 문장→논리는 문자열 생성보다 실행·충족가능성·정답 동치 검증으로 이동하고 있다.
  2. KG 추론은 최종 답만 평가하지 않고 검색 경로의 충분성과 unsupported claim을 분리한다.
  3. 멀티에이전트 신뢰는 agent의 선언·합의보다 코드 capability, 권한 경계, 메시지·task dependency의 실제 trajectory를 검사하는 방향이 강하다.
  4. RE:CHARGE에는 문장→중간표현→OWL/Z3 컴파일→reasoner/solver→근거·권한 gate가 가장 직접적인 통합 구조다.
  5. 멀티에이전트 조직에는 분산된 “모두의 안전 책임”보다 지정 Assurance Lead + 명시적 안전 명세 + tool-boundary enforcement가 더 강한 실험적 근거를 갖는다.
