# 개정 공통 브리프 (실무자 의견 8건 반영, 2026-11)

이 강의(`examples/attention-ko`)는 Vaswani et al., "Attention Is All You Need"(arXiv 1706.03762)를 한국어 인터랙티브 강의로 만든 것이다. 도메인 실무자 의견을 반영해 3단원을 6단원으로 개정한다. 너는 이 중 일부 파일만 맡는다.

## 실무자 의견 (전부 반영 대상)
1. 트랜스포머 이전 연구의 한계 설명 부족
2. RNN/LSTM의 한계 → 어텐션 등장 → LSTM 등에 붙여 사용 → 어텐션만으로 된 별도 네트워크 모듈이 필요해져 트랜스포머 등장, 이 배경 흐름을 보강
3. 현재 LLM 발전과 연결되는 부분이 재미있음
4. 셀프 어텐션과 크로스 어텐션이 왜 '셀프'이고 '크로스'인지 빠짐
5. 층의 개수와 위치(어디에 무엇이 몇 개)가 빠짐
6. 데이터 차원이 어텐션과 FFN을 거치며 어떻게 바뀌는지 보여 주기
7. 트랜스포머 설명이 빈약함. 보충자료 필요
8. 최근 동향, 최소한 encoder-only / encoder-decoder / decoder-only의 차이와 설명, 최근 decoder-only가 많이 쓰이는 이유

**설명을 줄이지 말고** 그림(인라인 SVG), 표, 구체 예시로 보강한다. 전문 용어에는 반드시 툴팁과 쉬운 풀이를 단다.

## 담당별 작업
### A: 00-background 수정 + 01-lineage 신규 (의견 1, 2, 3)
- 00: 기존 쪽을 유지한다. `연구 계보` 탐구 자료 쪽은 01로 **옮긴다**(01에서 노드를 늘려 확장). 첫 쪽 또는 요약에 "이 구조가 오늘날 LLM(GPT 등)의 뼈대가 되었다(6단원)"는 연결 문장을 하나 넣는다. 학습 목표·확인 문제가 옮긴 내용에 의존하면 맞게 고친다.
- 01(신규, 보충 단원이지만 논문 1·2절 내용은 paper-ref를 단다): 줄거리 순서
  1. RNN의 순차 계산: $h_t = f(h_{t-1}, x_t)$, 병렬화 불가, 먼 위치 사이 경로 길이 O(n) (논문 1절)
  2. 기울기 소실/폭주(Bengio 1994) → LSTM의 게이트(1997)로 완화, 그래도 순차성은 남음
  3. seq2seq(Sutskever 2014, Cho 2014): 입력 전체를 고정 길이 문맥 벡터 하나로 압축 → 긴 문장에서 병목 (그림: 긴 문장이 좁은 깔때기로 들어가는 SVG)
  4. Bahdanau 2014: 디코더가 단어마다 인코더의 모든 은닉 상태를 가중합 → **어텐션을 RNN에 붙여 사용**. Luong 2015: 내적 점수. (그림: RNN 인코더-디코더 위에 어텐션 화살표)
  5. 남은 문제: 어텐션은 붙었지만 RNN이 여전히 순차 → CNN 계열(ByteNet, ConvS2S)의 시도와 한계(경로 길이 log/선형) → 셀프 어텐션 선행 연구 → "RNN을 빼고 어텐션만으로 층을 쌓자" = 트랜스포머 (논문 1·2절)
  6. 확장된 연구 계보(lineage-tree): RNN → LSTM → seq2seq → Bahdanau → Luong → 셀프 어텐션 선행 → 트랜스포머, 옆 가지로 ByteNet/ConvS2S
  7. 비교 데이터 표: RNN / RNN+어텐션 / CNN / 트랜스포머를 병렬화, 최대 경로 길이, 고정 길이 병목 여부로 비교
  - 확인 문제 3~5문항

### B: 02-attention 추가 + 03-architecture 신규 (의견 4, 5, 6, 7)
- 02: 기존 쪽 유지. 멀티헤드 쪽 뒤(확인 문제 앞)에 쪽 2~3개 추가(논문 3.2.3절):
  - "셀프와 크로스, 이름의 이유": Q·K·V가 **같은 시퀀스**에서 나오면 셀프(자기 자신을 참조), Q는 디코더 / K·V는 **인코더 출력**에서 나오면 크로스(두 시퀀스를 가로지름). 논문은 크로스를 encoder-decoder attention이라 부름. 두 SVG를 나란히(같은 문장 예: "나는 학교에 간다" → "I go to school", 예시임을 밝힘). 점수 행렬 모양: 셀프 n×n, 크로스 n_tgt×n_src.
  - "마스크드 셀프 어텐션": 디코더는 미래 토큰을 보면 안 됨(자기회귀). 소프트맥스 전에 위쪽 삼각형을 −∞로 → 비중 0. 삼각 마스크 행렬 SVG. 학습할 때 출력을 한 칸 밀어 넣는 이유.
  - 세 가지 쓰임 요약 표(위치, Q 출처, K·V 출처, 마스크 여부).
  - 확인 문제에 셀프/크로스 1문항 추가(문제 쪽당 최대 2문항).
- 03(신규, 논문 3.1, 3.3, 3.4, 3.5, 4절. paper-ref 단다):
  1. 전체 구조도(논문 그림 1을 인라인 SVG로 다시 그림): 왼쪽 인코더 층 ×N=6 [멀티헤드 셀프 → Add&Norm → FFN → Add&Norm], 오른쪽 디코더 층 ×N=6 [마스크드 셀프 → Add&Norm → 크로스 → Add&Norm → FFN → Add&Norm], 아래 임베딩+위치 인코딩, 위 선형+소프트맥스. **인코더 마지막(6번째) 층 출력이 디코더 6개 층 모두의 크로스 어텐션 K·V로 들어감**을 화살표로.
  2. 층 안 부품: 잔차 연결과 LayerNorm(x + Sublayer(x)), 왜 모든 하위 층 출력을 d_model=512로 맞추는가(잔차 덧셈을 위해)
  3. FFN: 식, 512→2048→512, 위치마다 독립 적용, 층마다 다른 파라미터
  4. 위치 인코딩: 왜 필요한가(순서 정보 없음), 사인·코사인 식, 임베딩에 더함, 학습형도 거의 같음(표 3 E)
  5. **텐서 모양 따라가기**(수식 단계 풀이 마크업, research.md의 유도 그대로): 단계마다 모양을 보여 주고, 핵심 정리 "층을 지나도 n×512가 유지되므로 같은 층을 N번 쌓을 수 있다"
  6. 기본/큰 모델 하이퍼파라미터 데이터 표(N, d_model, d_ff, h, d_k, P_drop, 파라미터 65M/213M, 학습 12시간/3.5일)
  7. 왜 셀프 어텐션인가(4절 표 1): 복잡도, 순차 연산, 최대 경로 길이 데이터 표 + n<d일 때 빠름 + 긴 문장에서는 n² 부담(해석 콜아웃)
  - 확인 문제 3~5문항(텐서 모양 계산 문항 1개 포함)

### C: 04-results 추가 + 05-trends 신규 (의견 3, 5, 7, 8)
- 04: 기존 쪽 유지. 표 3 (C) 행(층 수 N=2/4/6/8, d_model, d_ff 변화)을 어블레이션 토글 또는 데이터 표로 쪽 하나 추가하고, "큰 모델이 더 좋다"(6.2절)와 파라미터 증가를 함께 해석한다. (E) 행(학습형 위치 임베딩)도 한 줄 언급. 문항 1개 추가 가능.
- 05(신규, 논문 밖 보충이라 paper-ref 달지 않는다. 첫 쪽 콜아웃에 "논문 이후의 보충 내용"임을 밝힌다):
  1. 트랜스포머 이후 세 갈래: encoder-only(BERT), encoder-decoder(원 논문, T5, BART), decoder-only(GPT 계열). 4단원 구조도의 왼쪽만/둘 다/오른쪽만 쓴다는 연결.
  2. 어텐션 마스크 모양 SVG 3개(양방향 전체 / 인코더 전체+디코더 삼각 / 삼각)
  3. 세 계열 비교 데이터 표: 보는 방향, 사전학습 목표(MLM / span 잡음 제거 / 다음 토큰 예측), 대표 모델, 잘하는 일(분류·추출 / 번역·요약 / 생성 전반)
  4. 왜 decoder-only가 많이 쓰이나: research.md의 4가지 근거. 논문 실험 근거(Wang et al. 2022)와 실무적 이유를 구분하고, "멀티태스크 미세조정 조건에서는 비인과 모델이 앞섰다"는 단서를 꼭 쓴다. KV 캐시 그림 1개 권장.
  5. 원 논문 이후 바뀐 부품: Pre-LN, RoPE, GQA, MoE 등. **각 항목은 WebSearch로 원문(arXiv)을 확인한 뒤** `briefs/research.md`의 "이후 동향" 절에 출처와 함께 추가하고 쓴다. 확인 못 하면 빼라.
  6. 더 읽을거리 콜아웃(research.md 보충자료 링크)
  - 확인 문제 3~5문항

## 형식 제약
- 한 화면 = `.screen.cornell` 1장. 1440×900에서 쪽 높이 765px 이하여야 한다(넘치면 쪽을 나눈다).
- 단원마다 본문 쪽 3~8개(확인 문제 쪽 제외), 확인 문제 3~5문항, 문제 쪽당 최대 2문항. 그중 하나 이상은 부정형(`옳지 않은 것은?`) 또는 `<보기>`형.
- 단원 첫 쪽은 `.module-header` 다음 쪽이며, 단서 칸(cue)에 `학습 목표` 2~3개(`~을 설명할 수 있다.`).
- 화면 제목 끝 논문 위치 태그 `<span class="paper-ref">논문 N절</span>`은 논문 내용일 때만 단다.
- 용어: 첫 등장에 `term` 툴팁(`data-definition`은 사전식 명사형 종결, 예: `…하는 것.`, `…함.`)과 terms.md의 첫 등장 표기를 쓴다. 이후 표기를 통일한다.
- id는 강의 전체에서 유일해야 한다. 새 id, SVG marker id, 퀴즈 id, 토글 id에는 위 표의 파일 접두사를 붙인다.
- 출처는 그림 캡션이나 본문에 `<a href="…" target="_blank" rel="noopener">`로 단다. `<img>`·`<script>`·`<link>`로 외부 자원을 불러오지 않는다(빌드가 실패한다).
- 색: 먹색과 교과 색(`accent` 클래스)만 쓴다. 다른 유채색은 금지.
- 기존 설명을 삭제하거나 축약하지 않는다(A의 계보 쪽 이동은 예외).
- 맡은 파일 외에는 수정하지 않는다(C의 research.md 추가는 예외). git commit 하지 않는다.

## 검증 (맡은 파일을 다 쓴 뒤 반드시 실행, 저장소 루트에서)

bash examples/attention-ko/build.sh

- 마지막 보고: 추가·변경한 쪽 제목 목록, 문항 수, 사용한 출처, 남은 문제.
