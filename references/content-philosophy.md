# 콘텐츠 철학 — 학술 논문 가르치기

> **읽는 시점:** 3.5단계(브리프)·4단계(모듈 HTML). 모든 콘텐츠 결정의 기준. 문체는 `korean-style-guide.md`, 번역어는 `glossary-ko.md`. 본문은 한다체이고 따옴표 안 예시가 본문 문장이다.

## 핵심 원칙

### 큰 그림 먼저 (top-down)

서베이·장문 논문은 첫 모듈에서 분류·절 구성을 한 장의 지도로 보이고, 이후 모듈 도입마다 현재 위치를 짚는다. 출판 뒤 바뀐 것은 마지막 모듈에서 다룬다(서베이·리뷰 필수, 그 밖은 출판 1년 이상이면 권장).

### 방법마다 대가를 보인다

방법·패러다임마다 단점·비용(지연, 호출 수, 저장, 조정할 값)과 실패하는 입력 예를 같은 화면이나 바로 다음 화면에 둔다. 예: "dense retrieval은 뜻이 같은 문서를 찾지만, 드문 고유명사·오류 코드·부정 표현에서는 BM25보다 못할 수 있다." 실패 예는 1차 출처 수치나 "예시"라고 밝힌 자체 예.

### 지표는 계산으로 가르친다

precision, recall, F1, EM 등이 처음 나오면 작은 수치 예(정답 문서 3개, 검색 5개 중 2개 적중 등)를 그림으로 그리고 단계별로 계산한다. 매개변수(top-$k$ 등)에 따른 변화를 토글로 보이면 더 좋다.

### 설명을 줄여서 쉽게 만들지 않는다

어렵다는 피드백에는 설명을 빼지 말고 그림·구체 예시·용어 풀이를 더한다.

### 직관 먼저, 형식은 나중에

모든 수식·알고리즘 앞에 하는 일을 일상어로 푼 문장을 둔다. 예: "손실 함수는 모델이 자신의 답에 얼마나 놀라는지를 나타내는 값이다. 모델이 예상한 답과 정답이 다를수록 손실이 커진다." → $L = -\log P(y|x)$.

### 논문의 이야기

각 모듈은 절 요약이 아니라 논문 서사의 한 장이다. 예: "이 논문의 연구진은 강화학습 훈련이 정체되는 문제를 발견하고, 프롬프트에 의미 없는 문장을 덧붙이는 반직관적 방법을 시도하였다. 그 결과 성능이 향상되었다."

### 보여 주기, 말하지 않기 — 시각 우선

- 텍스트 블록은 2~3문장 이내. 화면의 절반 이상은 시각 요소(다이어그램, 수식, 카드, 애니메이션, SVG).
- 바꾸기: 3개 이상 나열·방법 목록 → 개념·패턴 카드 / 순서·파이프라인 → 단계 카드, SVG 흐름도, 데이터 흐름 애니메이션 / 실험 구성 → SVG 구조도 / 결과 비교 → 인터랙티브 비교 막대 / 연구 간 관계 → 계보 트리(SVG 또는 HTML)

### 화면 하나에 개념 하나

화면 하나에 아이디어 하나. 빽빽하면 화면을 추가한다.

### 그림·첫 페이지·계보·쪽 규칙 (요약)

- **개념 그림:** 새 개념·알고리즘·수식마다 코드 그림 하나, 숫자는 본문과 같게(`illustration.md` §3, `interactive-elements.md` "개념 그림").
- **첫 페이지:** 1단원 첫 페이지에 왜 썼는가(이전 방식의 한계)와 새로운 점(논문 수치 근거)을 한 장에(`interactive-elements.md` "첫 페이지").
- **연구 계보:** 갈래마다 이어받은 것과 달라진 것, 루트에 한 줄 기여.
- **한 쪽 = 한 화면:** 765px 안에서 스크롤 없이. 넘치면 나눈다.
- **해석의 표시:** 강의는 논문의 요약·이해 보고이다. 논문이 직접 말하지 않은 해석은 내용 판단에 근거해 쓰되 해석임을 드러낸다(`논문은 ~라고 보고한다. 이는 ~로 해석할 수 있다.`).

### 원문 그대로가 아니라 풀이

원문 인용은 핵심 정의·주장에 한해 최소로, 따옴표와 출처로 구별한다.

### 비판적 읽기

- 결과마다 "이 차이는 유의미한가?", 방법 선택마다 "왜 다른 방법이 아니라 이 방법인가?"를 묻는다.
- 한계를 드러낸다. 데이터셋 하나로만 평가했거나 개선 폭이 오차 범위 이내이면 명시한다.

### 지식 확장 — 논문 너머

선수 개념(수학·알고리즘·분야 개념), 관련 연구(다른 시도와의 차이), 연구 맥락(분야 흐름 속 위치)을 다룬다. 가장 중요한 관련 논문 3~5편은 각각 인용 카드로.

### 안내된 진입 — 본론 전에 배경

문제 제기로 바로 시작하지 않는다. 모듈 0은 논문에 없는 선수 학습 전용으로, 모듈 1의 기여를 이해할 어휘·사고 모형을 갖추게 한다(id·파일 `module-0`/`00-`, 화면 번호 1, 제목은 `배경 지식`처럼 간결히).

- 선수 개념 3~5개를 직관 먼저, 필요할 때만 형식 표현으로.
- "지식 지도" SVG로 개념 간 연결.
- "필요한 배경"과 "논문의 주장"을 구분. 표준은 화면 맨 위 `배경 지식` 콜아웃(`callout callout-info`, `interactive-elements.md` 모듈 골격 절).
- 끝에 `확인 문제` 3~5문항, 1개 이상 부정형(`옳지 않은 것은?`) 또는 보기형.

### 학습서 흐름

**학습 목표 → 개념 설명 → 개념 체크 → 탐구 자료 → 핵심 정리 → 확인 문제**

| 코너 | 역할 | 작성 지침 |
|---|---|---|
| 학습 목표 | 첫머리 2~3개 | `~을 설명할 수 있다.`처럼 행위 동사. "이해한다", "안다" 금지 |
| 개념 설명 | 직관 → 수식 → 의미 | 한다체 평서. 본문 정의 `A는 B이다.`/`A란 B를 말한다.`, 툴팁·용어 정의는 사전식 명사형 |
| 개념 체크 | 짧은 문항·빈칸 | 방금 설명한 개념을 즉시 점검 |
| 탐구 자료 | 그림, 표, 실험 결과, 연구 대화 | 제시 뒤 `이 자료에서 알 수 있는 것은?` |
| 핵심 정리 | 모듈 끝 요약 | 핵심 통찰 |
| 확인 문제 | 모듈 끝 3~5문항 | 부정형·보기형 1개 이상, "퀴즈 철학" |

강조 상자: 핵심 통찰 → `핵심 정리`, 부가 사실·배경·사례 → `보충 설명`, 논문 밖 확장 → `더 알아보기`. 감탄문, 느낌표, `여러분` 금지. 재미는 비유와 구체적 사례로.

### 기억에 남게 하기

방법·개념에 이름을 붙이고 비유·구체적 사례로 개성을 준다. 어조는 한다체.

### 용어 툴팁 — 빠뜨리는 용어 없이

모듈마다 전문 용어 첫 등장에 반드시, 적극적으로 단다: 수학 기호($\mathbb{E}$, $\arg\max$, 소프트맥스, KL 발산), 분야 용어(롤아웃, 이점 함수, 정책 경사, 퍼플렉서티), 약어(GRPO, PPO, RLHF, LoRA), 낯선 소프트웨어·모델 이름. 일반 교육 과정 용어(가설, 실험, 대조군 등)에는 달지 않는다.

**형식:** `한글 용어(English Term): 사전식 정의.` 괄호 반각(ASCII), 정의는 `~하는 값.`, `~을 나타냄.` 같은 명사형(KO111). 예: `정책 경사(Policy Gradient): 보상이 커지는 방향으로 정책 파라미터를 직접 갱신하는 최적화 방법.` 번역어는 코스 용어표(`glossary-ko.md` 기준)를 따르고 모듈마다 바꾸지 않는다.

### 시각적 설명을 위한 SVG 다이어그램

인라인 SVG: 개념 관계도, 계보 트리, 실험 구성 개요, 알고리즘 순서도, 비교 행렬. 디자인 시스템 CSS 변수(색, 글꼴, 모서리 반경, 그림자), `viewBox` + `width="100%"`. 한글 라벨은 글자당 약 1em이므로 폭에 여유(`gotchas.md`).

## 퀴즈 철학

암기가 아니라 적용을 확인한다. 학습서 문항 형식.

- **발문:** `다음 중 ~에 대한 설명으로 옳은 것은?` / `다음 중 ~으로 옳지 않은 것은?` / `<보기>에서 ~인 것만을 있는 대로 고른 것은?`(보기 ㄱ, ㄴ, ㄷ, 선택지 `ㄱ, ㄴ`처럼 조합). 주관식은 `~하시오.`
- **선택지:** 원문자 ①②③④. 오답도 그럴듯한 오개념에서.

**출제 대상 (가치 순)**
1. **예측 상황** — 설정이 바뀌면? `다음 중 보상 모델 없이 훈련할 때 나타날 결과로 가장 타당한 것은?`
2. **원인 추론 상황** — 예상 밖 결과의 설명. `다음 중 [그림]의 손실 곡선이 중간에 급증한 원인으로 가장 타당한 것은?`
3. **설계 결정** — X 대신 Y인 이유. `다음 중 연구진이 배치 크기를 키운 이유로 옳은 것은?`
4. **비판적 읽기** — 데이터가 뒷받침하지 않는 결론. `다음 중 [표]에서 도출한 결론으로 옳지 않은 것은?`
5. **추적 연습** — 입력→출력 경로. `<보기>의 입력이 알고리즘을 통과할 때 3단계 직후의 값을 구하시오.`

**출제하지 않는 것:** 정의(툴팁 담당), 단순 사실(저자, 연도), 위로 스크롤해 베낄 수 있는 문제.

**해설 문체**
- `main.js`가 `정답`/`오답` 표지를 자동으로 붙이므로 속성에 쓰지 않는다. 형식 `~이므로 ~이다.`, 오답 해설에는 오답지 분석 한 줄(`①은 ~이므로 옳지 않다.`).
  - `data-explanation-right="② | 보상 모델이 없으면 정책이 기준 없이 갱신되므로 훈련이 불안정해진다."`
  - `data-explanation-wrong="| 정답은 ②이다. 보상 모델이 없으면 정책이 기준 없이 갱신되므로 훈련이 불안정해진다. ①은 보상 모델과 무관한 절차이므로 옳지 않다."`
  - 화면: **정답** ② | … / **오답** | 정답은 ②이다. … (KO110)
- `$…$` 수식 가능(`main.js`가 삽입 뒤 KaTeX 재렌더링).
- 오답 해설은 어느 부분이 왜 틀렸는지 근거와 함께 한 줄. 칭찬("훌륭하다", "잘했다"), 격려, 감탄, 느낌표, 처벌적·점수 중심 어조 금지.
