# 모듈 브리프 템플릿

> **읽는 시점:** 병렬 경로로 복잡한 논문을 다루는 3.5단계. 모듈마다 하나씩 채워 `course-name/briefs/0N-slug.md`로 저장한다.
> 한국어로 쓰고, 학습 목표와 코스 문구 예시는 한다체. 기준은 `references/korean-style-guide.md`, 용어는 `references/glossary-ko.md`.

---

## 모듈 N: [제목]

- **논문 절 번호·제목:** [`.module-number` = 1부터 연속 정수(논문 절 번호 아님), `.module-title` = 논문 절 제목의 한국어 번역(예: `어텐션`, `결과`). 교재식 제목을 새로 짓지 않는다. id·파일명(`module-0`, `00-`)만 0부터(모듈 0 = 화면 번호 1).]

### 학습 목표
2~3개, `~할 수 있다.` 형식. 행위 동사(설명하다, 비교하다, 구하다, 판단하다), "이해한다"·"안다" 금지.
- [예: 손실 함수의 값이 커지는 조건을 설명할 수 있다.]
- [예: 두 방법의 훈련 곡선을 비교할 수 있다.]

### 서사 구조
- **직관:** [형식 표현 전, 핵심 아이디어를 담은 일상어 한 문장]
- **도입 질문:** [첫 페이지에 한다체 발문 최대 1개. 관심을 끄는 질문이나 상황]
- **핵심 통찰:** [반드시 가져가야 할 한 가지]
- **논문과의 연결:** [이 모듈이 논문 서사에서 맡는 역할]

### 맡은 논문 그림·표
`briefs/figures.md`에서 이 모듈에 배정된 그림·표를 빠짐없이 적는다.
- [그림 n | 그림이 말하는 것 | 대신 쓸 새 예시(한국어) | 재현 방식(전용 쪽 SVG·차트·표·따라가기) | 놓을 쪽 제목]
- 결과 그래프는 원문 수치를 그대로 쓰고, 읽는 법만 다른 예시로 푼다.

### EBS 코너 배치
흐름: `학습 목표 → 개념 설명 → 개념 체크 → 탐구 자료 → 핵심 정리 → 확인 문제`.
- **개념 체크:** [개념 설명 직후 짧은 점검 문항 또는 빈칸. 예: `학습 목표 1`과 연결된 한 문항]
- **탐구 자료:** [제시할 그림, 표, 실험 결과, 연구 대화와 물을 것]
- **핵심 정리:** [핵심 통찰 2~3개와 전략 한 줄(`~하라.`)]
- **보충 설명 / 더 알아보기:** [필요할 때만, 합쳐서 모듈당 최대 2개. 부가 사실이나 논문 밖 확장]
- **확인 문제:** [3~5문항, 1개 이상 부정형(`옳지 않은 것은?`) 또는 보기형. 발문 `다음 중 ~으로 옳은 것은?`, 선택지 ①②③④]

### 대가와 실패 사례
소개하는 방법·패러다임마다 적는다. 비워 두지 않는다.
| 방법 | 단점·비용 | 실패하는 입력 예 | 출처(1차) 또는 "예시" |
|---|---|---|---|

### 지표 계산 예
처음 나오는 지표마다 작은 수치 예와 계산 결과(그림의 값과 같게).
- [예: 정답 문서 3개, top-5 중 2개 적중 → Precision@5 = 0.40, Recall@5 ≈ 0.67, F1 = 0.50]

### 화면별 계획 (코넬 페이지)
모든 화면은 코넬식 한 페이지. 페이지마다:
- **핵심 질문(`.cue`):** [2~4개, 한다체 의문형. 예: 어텐션은 무엇을 계산하는가?]
- **노트 내용(`.notes`):** [화면 제목, 코너 이름, 본문·수식·그림·요소]
- **한 문장 요약(`.summary`):** [한다체 한 문장]
- **쪽 맞춤:** [1440×900(내비게이션 제외 약 765px)에 스크롤 없이 들어가는가? 넘치면 나눈다. 높은 SVG·표는 높이를 적고, 퀴즈는 페이지당 4문항 이하]

### 이 모듈에서 쓰는 용어
코스 용어표에서 이 모듈 항목만 발췌한다. 번역어를 새로 만들지 않으며, 새 용어는 용어표에 먼저 추가한다.

| English | 한국어 표기 | 첫 등장 표기 | 처음 나오는 모듈 | 비고 |
|---|---|---|---|---|
| Policy Gradient | 정책 경사 | 정책 경사(Policy Gradient) | 모듈 3 | [툴팁 정의(사전식 명사형): 보상이 커지는 방향으로 정책 파라미터를 직접 갱신하는 최적화 방법.] |

(열은 `briefs/terms.md`와 같은 5개. 약어는 `한글 풀이(English Full Name, ACRONYM)`.)

### 첫 페이지 구성 (1단원만)
- **문제 문단:** [이전 방식의 한계와 동기 2~3문장]
- **비교 그림:** [이전 방식 대 제안 방식, 같은 입력, 핵심 비교]
- **새로운 점:** [3개 이내, 항목마다 이름 + 논문 수치 근거]

### 화면별 `.paper-ref`
논문 밖 화면(배경 지식, 확장)은 `없음`으로 적고 태그를 붙이지 않는다.
- [화면 제목 → 논문 3.2.1절 / 없음]

### 페이지의 주 버튼
Space 키는 페이지의 주 버튼을 누른다. 주 인터랙티브 요소는 가능하면 페이지당 하나.
- [화면 제목 → 수식 유도 / 의사코드 풀이 / 확인 문제 / 없음]

### 문체 확인 항목
작성 뒤 확인한다.
- [ ] 본문·학습 목표·해설이 한다체. `~합니다`, `~해요`, `여러분`, 느낌표 없음.
- [ ] 학습 목표가 `~할 수 있다.`로 끝난다.
- [ ] 발문이 `다음 중 ~은?` 형식, 선택지에 ①②③④.
- [ ] 해설이 `~이므로 ~이다.`, 칭찬 없음. 오답 해설에 `①은 ~이므로 옳지 않다.` 한 줄.
- [ ] 용어가 코스 용어표와 일치하고 첫 등장 툴팁이 `한글 용어(English Term): ~하는 값.` 같은 사전식 명사형(KO111).
- [ ] 핵심 정리 끝에 `~하라.` 전략 한 줄. 모듈 제목·번호가 논문 절을 따른다.
- [ ] 번역투(`~에 의해`, `~를 가지고 있다`, `~되어진다`) 없음.
- [ ] 약어·수식 뒤 조사가 읽는 소리에 맞는다.
- [ ] 괄호가 반각, 한자·중국어 없음.
- [ ] `python3 references/lint-ko.py <course-dir>` 통과.
