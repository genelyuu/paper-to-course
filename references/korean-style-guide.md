## 0. 적용 범위와 우선순위

- **적용 대상:** 학습자에게 보이는 모든 생성물. 본문, 콜아웃, 카드, 용어 툴팁 정의(`data-definition`), 퀴즈 발문·선택지·해설(`data-explanation-*`), UI 안내 문구, 그림 캡션, 표.
- **적용 제외:** 작성자용 지시문(SKILL.md, 브리프 등), 코드 블록, 수식 내부, 논문 원문 인용(`lang="en"` 요소).
- **우선순위:** 언어(문체·용어·조사·띄어쓰기·문장 부호)에 관한 한 **이 가이드 > 다른 references 문서의 예시**이다. `interactive-elements.md`, `content-philosophy.md` 등의 예시 문구가 이 가이드와 어긋나면 이 가이드를 따른다. HTML 구조·클래스·디자인은 해당 문서를 따른다.
- **용어 우선순위:** 코스 용어표(§2.6) > `glossary-ko.md` > 이 가이드의 결정 절차(§2.3).

## 1. EBS 교재 문체

근거: EBS 수능특강의 코너 구성(개념 체크, 탐구 자료, 2점·3점 테스트)과 평가원 발문 "옳은 것만을 <보기>에서 있는 대로 고른 것은?"은 검색 요약으로 확인했다. 종결어미·발문 형식을 규정한 공개 집필 지침은 찾지 못했으므로 나머지 규칙은 EBS·검정 교과서의 **(관행)**이다.

### 1.1 본문: 한다체 평서형

- 종결은 `~이다 / ~한다 / ~된다 / ~할 수 있다 / ~이므로 ~이다`로 쓴다. `~합니다`, `~해요`, `~하십시오`는 쓰지 않는다. (린터 KO102)
- 독자를 직접 부르는 `여러분`을 쓰지 않는다. (KO109)
- 수사적 의문문과 감탄문(`!`)은 쓰지 않는다. 의문문은 발문(§1.3)에만 쓴다.
- 정의 문장은 `A는 B이다` 또는 `A란 B를 말한다`. 핵심어는 굵게(`<strong>`) 표시하고 이탤릭은 쓰지 않는다.
- 한 문장에 한 가지 주장. 한 문단은 3문장 이하. (KO106)

| ✗ | ✓ |
|---|---|
| LoRA는 가중치 행렬을 직접 바꾸지 않습니다. | LoRA는 가중치 행렬을 직접 바꾸지 않는다. |
| 여러분은 이제 어텐션이 왜 필요한지 궁금할 거예요! | 어텐션이 필요한 이유는 다음과 같다. |
| 그렇다면 PPO는 왜 가치 함수가 필요할까요? | PPO는 어드밴티지를 추정하려고 가치 함수를 학습한다. |
| 놀랍게도 모델 크기를 늘리자 성능이 급격히 좋아졌습니다! | 모델 크기가 일정 규모를 넘자 정확도가 크게 올랐다. |
| 셀프 어텐션은 아주 중요한 개념이에요. | **셀프 어텐션**은 한 시퀀스 안의 토큰끼리 서로 참조하게 하는 연산이다. |

### 1.2 학습 목표: `~할 수 있다.`

- 모듈 맨 앞에 2~3개. 도입 문장은 `이 모듈을 학습하면 다음을 할 수 있다.`
- 행위 동사(설명하다, 비교하다, 구하다, 계산하다, 구분하다, 해석하다, 판단하다, 적용하다)를 쓴다. `이해한다`, `안다`, `익힌다`는 성취를 확인할 수 없으므로 쓰지 않는다. (관행)

| ✗ | ✓ |
|---|---|
| 트랜스포머를 이해한다. | 셀프 어텐션의 계산 과정을 설명할 수 있다. |
| GRPO에 대해 알아봅시다. | GRPO와 PPO의 어드밴티지 계산 방식을 비교할 수 있다. |
| 손실 함수를 배운다. | 교차 엔트로피 손실의 값을 주어진 확률로 구할 수 있다. |

### 1.3 발문과 선택지

발문 패턴 (관행. 마지막 `<보기>` 형식은 평가원 예시로 확인):

| 유형 | 발문 |
|---|---|
| 긍정형 | `다음 중 GRPO에 대한 설명으로 옳은 것은?` |
| 부정형 | `제거 실험 결과에 대한 해석으로 옳지 않은 것은?` (`않은`에 밑줄 `<u>않은</u>`, 관행) |
| 보기형 | `LoRA에 대한 설명으로 옳은 것만을 <보기>에서 있는 대로 고른 것은?` |
| 자료형 | `표는 모델 크기별 정확도이다. 이에 대한 해석으로 옳은 것은?` |
| 서술형 | `식 (3)에서 $\beta$가 하는 역할을 한 문장으로 쓰시오.` / `어드밴티지 $A_i$를 구하시오.` |

- 선택지 텍스트 앞에 원문자 `①②③④⑤`와 공백 한 칸을 둔다. `확인 문제`는 5지 선다가 원칙이고, `개념 체크`는 2~4지도 쓴다. 번호는 ①부터 빠짐없이 이어 쓴다. `data-value`, `data-correct` 값은 원문자와 무관하게 `option-a` 형식을 유지한다.
- 선택지가 문장이면 한다체로 끝내고 마침표를 찍는다. 명사구면 마침표를 찍지 않는다.
- 배점 표시가 필요하면 발문 끝에 `[3점]`을 붙인다. 2점 문항은 생략한다. (관행)
- `<보기>`는 HTML 텍스트에서 `&lt;보기&gt;`로 이스케이프한다. 보기 진술은 `ㄱ.`, `ㄴ.`, `ㄷ.`으로 시작하고, 선택지는 `① ㄱ ② ㄴ ③ ㄱ, ㄴ ④ ㄴ, ㄷ ⑤ ㄱ, ㄴ, ㄷ`처럼 조합한다.
- `<보기>` 상자는 `styles.css`의 `.bogi` 클래스를 쓴다. 발문(`h3.quiz-question`) 바로 아래에 `<div class="bogi"><p>ㄱ. …</p><p>ㄴ. …</p></div>`로 넣는다. 상자 제목 `<보기>`는 CSS가 자동으로 표시하므로 HTML에 쓰지 않는다.

| ✗ | ✓ |
|---|---|
| GRPO에 대해 맞는 걸 골라 보세요! | 다음 중 GRPO에 대한 설명으로 옳은 것은? |
| 어떤 게 틀린 설명일까요? | 기준 모델과의 비교 결과에 대한 해석으로 옳지 <u>않은</u> 것은? |
| A) 학습률이 크다 | ① 학습률이 너무 크면 손실이 발산할 수 있다. |
| 식 3의 베타가 뭘 하는지 써 봐요. | 식 (3)에서 $\beta$가 하는 역할을 한 문장으로 쓰시오. |

### 1.4 해설과 피드백

- 형식: `정답 ② | ~이므로 ~이다.` 정답 번호, 세로 막대, 근거 순. 오답 선택지 해설은 `① ~이므로 옳지 않다.`처럼 한 줄씩 쓴다. (번호·정답·근거 순은 EBS 해설집 검색 요약으로 확인, 세부 형식은 관행)
- 칭찬·격려·감탄(`잘했다`, `훌륭`, `!`)을 쓰지 않는다. (KO108)
- **퀴즈 속성 주의:** `main.js`가 피드백 앞에 `<strong>정답</strong>` 또는 `<strong>오답</strong>`을 자동으로 붙인다. 따라서 속성값을 `정답.`이나 `오답.`으로 시작하면 표지가 두 번 나온다.
  - `data-explanation-right="② | 그룹 안 모든 응답의 보상이 같으면 각 보상과 평균의 차이가 0이므로 어드밴티지가 0이다."` → 화면: **정답** ② | 그룹 안 ……
  - `data-explanation-wrong="| 정답은 ②이다. 그룹 안 모든 응답의 보상이 같으면 ……이므로 어드밴티지가 0이다."` → 화면: **오답** | 정답은 ②이다. ……
- 정적인 `정답과 해설` 블록(스크립트 없이 쓰는 해설)에는 `정답 ② |`를 직접 쓴다.
- 속성값 안 인용은 곡선 따옴표 `“ ”`를 써서 HTML 따옴표와 충돌하지 않게 한다.

| ✗ | ✓ |
|---|---|
| 정답이에요! 핵심을 정확히 짚었어요. | 정답 ② \| KL 페널티가 커지면 정책이 기준 모델에서 멀어지기 어려우므로 보상 해킹이 줄어든다. |
| 아쉬워요. 다시 생각해 볼까요? | 오답 \| 정답은 ③이다. 학습률이 너무 크면 갱신 폭이 최솟값을 지나치므로 손실이 발산한다. |
| 정답. 정답. 어드밴티지가 0이 된다. (표지 중복) | `data-explanation-right="② \| …"` |

### 1.5 UI 지시 문구: `~하시오`

- 안내 문장은 `~하시오`로 끝낸다. 버튼 레이블은 짧은 명사구(`정답 확인`, `다시 풀기`, `다음`, `전체 재생`)로 쓴다.
- `main.js` 사전의 한국어 문구(`먼저 답을 고르시오.` 등)와 같은 어미를 쓴다.

| ✗ | ✓ |
|---|---|
| 버튼을 클릭해 보세요! | 버튼을 눌러 다음 단계를 보시오. |
| 카드를 끌어다 놓아 주십시오. | 각 용어를 알맞은 정의에 끌어다 놓으시오. |
| 슬라이더를 움직여 보면 재밌어요. | 슬라이더로 학습률을 바꾸고 손실 곡선의 변화를 관찰하시오. |

### 1.6 예외: 연구 대화(채팅) 대사

- `.chat-window` 안의 등장인물 대사는 해요체를 허용한다. EBS 탐구 자료의 `학생 A:` 대화처럼 **인용된 말**이기 때문이다. 린터도 chat 계열 클래스 안에서는 KO102·KO108·KO109를 검사하지 않는다.
- 등장인물 이름: `학생 A`, `학생 B`, `교사`, `저자`, `리뷰어`. 실존 연구자 이름을 대사 화자로 쓰지 않는다.
- 대사여도 용어 표기(§2), 조사(§3), 띄어쓰기(§4)는 지킨다. 대화 앞뒤의 설명 문장은 한다체이다.

| 위치 | 예 |
|---|---|
| 대사(허용) | 학생 A: 이거 그냥 데이터 증강 아닌가요? |
| 대사(허용) | 리뷰어: 기준 모델을 같은 계산량으로 학습했는지 확인해야 해요. |
| 대화 뒤 설명(한다체) | 두 사람의 대화는 데이터 증강과 프롬프트 교란의 차이를 보여 준다. |

### 1.7 코너

코너 이름은 콜아웃의 `<strong class="callout-title">`에 그대로 쓴다(확인 문제는 `quiz-container` 앞의 화면 제목에 쓴다). 모듈 흐름은 `학습 목표 → 개념 설명 → 개념 체크 → 탐구 자료 → 핵심 정리 → 확인 문제`이다(`module-brief-template.md`와 같음). HTML 패턴은 `interactive-elements.md`의 클래스를 쓴다.

| 코너 | 용도 | HTML 패턴 | 문체·분량 |
|---|---|---|---|
| 학습 목표 | 모듈에서 할 수 있게 될 일 | `callout callout-info` + 제목 `학습 목표` + `<ol>` | `~할 수 있다.` 2~3개 |
| 개념 체크 | 방금 설명한 정의·용어의 즉시 확인 | `quiz-container`에 문항 1개, 또는 드래그 앤 드롭 매칭(용어↔정의) | 발문 1개, 2~4지 |
| 탐구 자료 | 실험 결과·그림·대화를 읽고 해석 | 결과 비교, 어블레이션 토글(화면 레이블은 `제거 실험`), SVG 다이어그램, 연구 대화(`chat-window`), 숨은 가정 찾기 | 자료 소개 1문장(`표는 ~이다.`) + 해석 또는 발문 |
| 보충 설명 | 알아 두면 좋은 배경, 원문 인용 | `callout callout-info` + 제목 `보충 설명` | 한다체 2~3문장 |
| 핵심 정리 | 모듈의 핵심 통찰 | `callout callout-accent` + 제목 `핵심 정리` | 한다체 2~4개 항목 |
| 더 알아보기 | 흔한 오해 바로잡기, 논문 밖 심화 | `callout callout-warning` + 제목 `더 알아보기` | 한다체 2~3문장 |
| 확인 문제 | 모듈 끝 평가 | `quiz-container`에 `quiz-question-block` 3~5개 | 5지 선다 원칙, 부정형 또는 보기형을 하나 이상 섞음 |

- **콜아웃 상한:** 선택 코너인 `보충 설명`·`더 알아보기`는 모듈당 합계 최대 2개이다. 고정 코너인 `학습 목표`·`핵심 정리`는 개수에 넣지 않는다. 모듈 0(id 기준 첫 모듈, 화면 번호 1)의 배경 표시(`배경 지식` 콜아웃)도 개수에 넣지 않는다(`interactive-elements.md` 모듈 골격 절).
- **확인 문제:** 모듈 끝에 3~5문항을 두고, 그중 하나 이상은 부정형(`옳지 않은 것은?`) 또는 보기형(`<보기>`)으로 한다.
- 기여 카드(`contribution-cards`), 단계 카드(`step-cards`), 흐름도는 개념 설명 본문에 쓰며 코너 이름을 붙이지 않는다.
- 개념 체크 예: 발문 `다음 중 임베딩에 대한 설명으로 옳은 것은?`, 선택지 `① 토큰을 정수 번호로 바꾸는 과정이다. ② 토큰을 실수 벡터로 나타낸 것이다. ③ ……`

### 1.8 교육 회사 학습서 문체: 글의 역할별 종결

EBS와 교육 회사(메가스터디, 이투스 등) 학습서는 한 권 안에서도 **글의 역할에 따라 종결 어미를 바꾼다**. 실제 학습서 본문 192쪽(지학사 『자신 있어, 어휘』 1·2단계, 『중등 수능 독해』 Level 2)에서 종결 유형을 센 결과와 이 스킬의 규칙은 다음과 같다.

| 글의 역할 | 관찰(건수) | 규칙 | 예 |
|---|---|---|---|
| 개념 설명 본문 | 한다체 평서 379 | 한다체(§1.1) | 어텐션은 쿼리와 키의 내적으로 비중을 정한다. |
| 용어 뜻풀이 | 명사형 종결 34 (`뜻을 새겨 가며 자세히 읽음.`) | **사전식 명사형 종결.** 툴팁 `data-definition`, 단서 칸 `<dd>`, 용어 정리 표 (KO111) | 소프트맥스(softmax): 실수 여러 개를 합이 1인 양수로 바꾸는 함수. 큰 값에 더 큰 비중을 줌. |
| 문항·활동 지시 | `~하시오` 120 | `~하시오`(§1.5) | 버튼을 눌러 다음 단계를 보시오. |
| 오답 해설 | 선지별 분석 (`① … ➡ … 언급되지 않았다.`) | 정답 근거 뒤에 **가장 그럴듯한 오답 하나**를 `①은 ~이므로 옳지 않다.`로 분석. 부정형 문항은 `③은 ~이므로 옳다.` | \| 정답은 ③이다. 표준편차가 8이므로 8로 나눈다. ⑤는 분산 64를 그대로 쓴 값이므로 옳지 않다. |

- 원 문자 뒤 조사는 읽는 소리(일·이·삼·사·오)를 따른다: `①은`, `②는`, `③은`, `④는`, `⑤는`.
- 메가스터디·이투스 교재 본문은 공개 원문을 확보하지 못했다. 공개 소개 자료로 확인한 것은 "오답 해설을 반드시 수록"(메가스터디북스)과 "이해할 개념과 약속으로 받아들일 개념을 구분"(이투스 강좌 소개)이다. 위 표의 건수는 지학사 표본에서만 센 값이다.

## 2. 용어 표기

### 2.1 첫 등장과 이후

- 모듈마다 첫 등장에서 `한글 용어(English term)`로 병기하고 툴팁(`.term`)을 단다. 이후에는 한글만 쓴다. 모듈은 따로 읽힐 수 있으므로 병기는 모듈 단위로 한다.
- 괄호는 ASCII 반각 `( )`. 괄호 앞에 공백을 두지 않는다. (KO103) 전각 괄호 U+FF08·U+FF09는 금지. (KO003)
- 괄호 안 영어는 Title Case로 쓴다(`정책 경사(Policy Gradient)`, `가능도(Likelihood)`). 모델·방법 이름과 약어는 논문 표기를 그대로 따른다(`BERT`, `GRPO`, `Adam`).
- 한자 병기는 하지 않는다. (KO002)
- 툴팁 정의 형식: `한글 용어(English Term): 사전식 명사형 종결 정의 1~2문장.` 예: `보상 모델(Reward Model): 응답의 좋고 나쁨을 점수로 매기는 모델. 사람의 선호 데이터로 학습함.` (KO107, KO111, §1.8)

| ✗ | ✓ |
|---|---|
| 정책 경사 (Policy Gradient) | 정책 경사(Policy Gradient) |
| 정책 경사（Policy Gradient） | 정책 경사(Policy Gradient) |
| Policy Gradient 방법은 … 이후에도 계속 영문 | 첫 등장 `정책 경사(Policy Gradient)`, 이후 `정책 경사` |
| 가능도(Likelihood)는 … 다음 문단에서 다시 가능도(Likelihood) | 두 번째부터 `가능도` |

### 2.2 약어

- **약어 첫 등장 형식(코스 전체의 단일 규칙):** `한글 풀이(English Full Name, ACRONYM)`로 쓰고, 이후에는 약어만 쓴다.
  - `저랭크 적응(Low-Rank Adaptation, LoRA)` → 이후 `LoRA`
  - `인간 피드백 기반 강화 학습(Reinforcement Learning from Human Feedback, RLHF)` → 이후 `RLHF`
- **예외(한 곳에서만 정한다):** 약어가 한국어 실무에서 이름처럼 굳었으면(GRPO, BLEU, GPU) `ACRONYM(English Full Name, 한글 풀이)`로 써도 된다. 예: `GRPO(Group Relative Policy Optimization, 그룹 상대 정책 최적화)`. 한 코스 안에서 같은 약어는 한 가지 형식만 쓴다.
- 한글 풀이가 주 표기인 용어(대규모 언어 모델)는 `대규모 언어 모델(Large Language Model, LLM)`로 쓴 뒤 문장 길이에 따라 `LLM`과 `대규모 언어 모델`을 함께 쓸 수 있다.
- 약어에 한글 명사를 붙여 조사 판단을 쉽게 한다: `CLIP 모델을`, `GPT 계열 모델이다`.

### 2.3 관용 음차 vs 번역: 결정 절차

`glossary-ko.md`에 없는 용어는 아래 순서로 정하고 코스 용어표(§2.6)에 기록한다.

0. **원어로 통용되는가(과한 한글화 금지)**: 국내 논문·기술 블로그·실무 대화에서 영어 그대로 쓰이는 개념어(retriever, reranking, chunking, fine-tuning, faithfulness, multi-hop)는 원어를 본문 표기로 쓰고, 첫 등장에 `reranking(재순위화)`처럼 한글 뜻을 괄호로 단다. 번역어가 검색되지 않거나 새로 만든 말(성찰 토큰, 부정 거부, 중간 망각)은 학습자가 원문·코드·문서와 연결하지 못하게 하므로 쓰지 않는다. 판단 기준은 "그 표기로 검색하면 관련 자료가 나오는가"이다. 원어 표기는 소문자 일반어(reranking), 고유 명칭은 원래 대소문자(Self-RAG, Lost in the Middle)를 따른다.
1. **고유 명칭·약어**(모델, 방법, 데이터셋, 지표 이름: Adam, BERT, ImageNet, BLEU)는 번역하지 않는다.
2. **번역어가 투명한가**: 한글만 보고 뜻을 짐작할 수 있으면 번역어 후보로 둔다(예: 보상 모델, 지식 증류).
3. **충돌이 없는가**: 같은 코스의 다른 핵심 용어와 같은 말이 되면 번역어를 버리거나 구별어를 쓴다(예: regularization `규제` vs normalization `정규화`).
4. **쓰임이 있는가**: Google 머신러닝 용어집 한국어판, 국내 교재·논문 번역 중 하나에서라도 쓰이는 표기를 우선한다. 새 번역어를 만들지 않는다.
5. **관용 음차가 굳었는가**: 2~4를 만족하는 번역어가 없거나 음차가 압도적으로 굳었으면(트랜스포머, 어텐션, 임베딩) 음차를 쓴다. 음차는 외래어 표기법(받침 7개, 파열음 된소리 금지, 굳은 관용 존중)을 따른다: `레이블`(라벨 아님), `윈도`, `파이프라인`. 
6. **전문 용어 띄어쓰기**: 단어별로 띄어 쓰는 것으로 통일한다(`경사 하강법`, `강화 학습`, `손실 함수`). 사전에 한 단어로 오른 말(`신경망`, `표준편차`, `기댓값`, `정확도`)은 붙인다. 전문 용어 띄어쓰기를 허용하는 한글 맞춤법 조항은 조사 문서에서 원문을 확인하지 못했다. (미확인)

### 2.5 금지·주의

- 같은 개념을 한 코스에서 두 표기로 쓰지 않는다(`미세 조정`과 `파인튜닝` 혼용 금지).
- 관용이 없는 음차를 만들지 않는다(`리워드 모델링` 대신 `보상 모델링`).
- 영어 단어를 조사만 붙여 본문에 노출하지 않는다(`reward가` → `보상이`).

### 2.6 코스 용어표 (필수)

- 코스를 시작할 때 논문의 핵심 용어 15~40개로 **코스 용어표**를 만들고, 모든 모듈 브리프의 "이 모듈에서 쓰는 용어"에 해당 행을 그대로 붙인다(`module-brief-template.md`).
- 열(5개, `briefs/terms.md`와 같음): `| English | 한국어 표기 | 첫 등장 표기 | 처음 나오는 모듈 | 비고 |`. 비고에 툴팁 정의가 필요한 이유나 `glossary-ko.md`와 다른 표기를 택한 근거(결정 절차 단계)를 적는다. 툴팁 정의문은 모듈 작성 때 사전식 명사형 종결(`~것.`, `~함.`, `~임.`, 명사)로 쓴다.
- `glossary-ko.md`와 다른 표기를 택하면 비고 열에 이유를 적는다. 모듈 작성 중 새 용어가 생기면 용어표에 먼저 추가한 뒤 쓴다.

## 3. 조사

- 조사는 앞말에 붙여 쓴다. 영문·숫자·수식 뒤 조사는 **읽는 소리**의 마지막 음절 받침으로 고른다. 국립국어원의 명시 규정은 확인하지 못했다((미확인), 언론·사전 관행).
- 단어로 읽는 약어는 단어 소리를 따른다(LoRA 로라, BERT 버트, GAN 간, CLIP 클립). 글자별로 읽는 약어는 마지막 글자의 이름을 따른다.
- **약어 읽기 규약:** 약어는 기본적으로 글자별로 읽는 것으로 보고 조사를 고른다. 용어집(`glossary-ko.md`)이 단어 읽기로 표시한 약어(예: NASA)만 단어 소리를 따른다. 따라서 RAG는 `RAG는`·`RAG를`(알에이지)로 쓴다. 린터 KO104도 같은 규약을 따른다.
- `(으)로`: 받침이 없거나 ㄹ 받침이면 `로`, 그 밖의 받침이면 `으로`.

10(십), 100(백), 1000(천), 10000(만)처럼 0으로 끝나는 수는 모두 받침이 있으므로 마지막 자리 0 규칙(`을/이/은/으로`)과 결과가 같다.

### 3.3 예

| 표기 | 읽기 | 맞는 조사 | 틀린 조사 |
|---|---|---|---|
| LoRA | 로라 | LoRA를, LoRA는, LoRA로 | LoRA을 |
| GPT-3 | 지피티 삼 | GPT-3은, GPT-3을 | GPT-3는 |
| GPT-4 | 지피티 사 | GPT-4는, GPT-4를 | GPT-4은 |
| PPO | 피피오 | PPO가, PPO를 | PPO이 |
| RLHF | 알엘에이치에프 | RLHF는, RLHF를 | RLHF은 |
| RNN | 알엔엔 | RNN이, RNN으로 | RNN가, RNN로 |
| LLM | 엘엘엠 | LLM은, LLM으로 | LLM는 |
| SFT | 에스에프티 | SFT를, SFT로 | SFT을 |
| BERT | 버트 | BERT를, BERT는 | BERT을 |
| 7B 모델 | 칠비 모델 | 7B 모델은 (명사를 붙이면 판단이 쉽다) | 7B은 |
| Adam | 아담 | Adam은, Adam으로 | Adam는 |
| CLIP | 클립 | CLIP을 (단어 읽기) | CLIP를 |

- **린터 한계:** KO104는 대문자 약어를 글자 이름으로만 판정한다. `CLIP을`처럼 단어로 읽는 약어가 자음으로 끝나면 오탐이 난다. 이 경우 `CLIP 모델을`처럼 명사를 붙여 피한다. 서술격 조사 `이다`(`GPT이다`)도 주격 `이`로 오판하므로 `GPT 계열 모델이다`처럼 고친다. 대소문자가 섞인 단어(LoRA, Adam)는 검사하지 않으므로 직접 확인한다.
- **알려진 린터 한계(WARN이 남아도 되는 경우):** 위 KO104의 서술격 `이다`·단어 읽기 약어 오탐이다. 명사를 붙여 피할 수 있으면 고치고, 문장상 피하기 어려워 남기면 최종 보고에 파일·줄과 함께 기록한다. 그 밖의 WARN은 모두 고친다.

## 4. 띄어쓰기·숫자·단위

- **숫자+단위는 붙여 쓴다.** 한글 맞춤법 제43항은 단위 명사를 띄어 쓰는 것이 원칙이나 아라비아 숫자 뒤에서는 붙여 쓸 수 있다(허용). 이 스킬은 붙여 쓰기로 통일한다: `3회`, `8개`, `2배`, `45분`, `3단계`, `5가지`. (KO105)
- 한글 수사 뒤 단위 명사는 띄어 쓴다: `세 가지`, `두 번`. 
- **라틴 단위 기호(SI·컴퓨팅 단위)는 숫자와 한 칸 띄운다:** `3 kg`, `10 ms`, `16 GB`. 한글 단위 명사(`3개`, `45분`)와 `%`, `%p`, `°`는 붙인다(`78.3%`, `90°`). `8GPU`보다 `GPU 8개`로 쓴다. 모델 규모 표기 `7B`, `1.7B`는 단위가 아니라 규모 약호이므로 붙인다. (SI 관행, `gotchas.md`와 같음)
- 의존 명사(것, 수, 때, 바, 만큼)는 띄어 쓴다: `학습할 수 있다`, `수렴할 때`. (일반 지식)
- **백분율:** `10%`처럼 붙인다. 두 백분율의 차이는 퍼센트포인트 `%p`로 쓴다: `정확도가 70.1%에서 73.3%로 3.2%p 올랐다.` 상대 향상률과 섞지 않는다. 첫 등장에 `3.2%p(퍼센트포인트)`로 풀 수 있다.
- **범위:** 물결표 `~`를 앞뒤 공백 없이 쓴다: `3~5`, `3~5개`, `2020~2024년`, `0.1~0.3`. 본문에서 하이픈 범위(`3-5`)를 쓰지 않는다. 수학 구간은 수식으로 쓴다: `$[0, 1]$`.
- **큰 수:** 아라비아 숫자 네 자리 이상은 세 자리마다 쉼표: `12,800`, `1,000`. 한글 단위를 섞을 때는 만 단위로 띄어 쓴다: `1억 2,000만`, `3조 5,000억`. 만 단위 띄어쓰기 조항은 조사 문서에서 원문을 확인하지 못했다. (미확인, 일반 지식)
- **영어 큰 수 환산:** 1M = 100만, 10M = 1,000만, 100M = 1억, 1B = 10억, 7B = 70억, 70B = 700억, 1T = 1조. 모델 규모는 원문 표기를 살리고 첫 등장에 풀이한다: `파라미터 70억 개 규모(7B)의 모델`, 이후 `7B 모델`. 토큰 수는 `2조 토큰`.
- **소수:** 소수점 앞 0을 쓴다(`0.5`, `.5` 아님). 논문 표의 유효 자릿수를 바꾸지 않는다. 반올림하면 `약`을 붙인다.
- **날짜:** `2024년 5월`, `2017년`.

| ✗ | ✓ |
|---|---|
| 3 단계로 나뉜다 | 3단계로 나뉜다 |
| 16GB 메모리, 40ms 지연 | 16 GB 메모리, 40 ms 지연 |
| 정확도가 3.2% 올랐다 (70.1→73.3) | 정확도가 3.2%p 올랐다 |
| 3 - 5 개의 샘플 | 3~5개의 샘플 |
| 1.2억개 파라미터 | 파라미터 1억 2,000만 개 |
| 열개의 응답 | 응답 10개 / 열 개의 응답 |

## 5. 문장 부호

2014년 개정 문장 부호 규정(문화체육관광부 고시 제2014-39호)을 따른다. 부호별 용법은 『문장 부호 해설』 원문을 직접 대조하지 못했다((일반 지식)).

| 부호 | 이 스킬의 표기 | 쓰임 |
|---|---|---|
| 큰따옴표 | `“ ”` (곡선) | 직접 인용, 논문 제목, 프롬프트 인용. HTML 속성값 안에서도 곡선 따옴표를 써 `"`와 충돌을 피한다. |
| 작은따옴표 | `‘ ’` (곡선) | 따옴표 안 인용, 처음 소개하는 말의 강조. 강조는 되도록 `<strong>`으로 한다. |
| 소괄호 | `( )` ASCII 반각 | 영어 병기, 보충. 앞에 공백 없음. 단, 식 번호 `식 (3)`은 띄운다. |
| 대괄호 | `[ ]` | 괄호 안의 괄호, 배점 `[3점]`, 인용문 안 보충. |
| 홑화살괄호 | `<보기>` | 문항의 보기 상자 이름. HTML 텍스트에서는 `&lt;보기&gt;`. |
| 가운뎃점 | `·` (U+00B7) | 짝이 되는 말 열거: `학습·검증·테스트 세트`, `2점·3점 테스트`. 한글 자모 `ㆍ`(아래아)로 대신하지 않는다. |
| 쌍점 | `A: B` | 앞말에 붙이고 뒤는 한 칸 띄운다: `정답: ②`, `학생 A: …`. 시각·비율은 앞뒤를 붙인다: `10:30`, `3:1`. |
| 줄임표 | `…` 또는 `……` | 생략. 한 코스에서 한 가지로 통일. 남용하지 않는다. |
| 물결표 | `~` | 범위(§4). 앞뒤 붙임. |
| 줄표·붙임표 | `―`는 쓰지 않음 | 부연은 괄호나 새 문장으로 쓴다. 하이픈은 고유 명칭(`GPT-4`, `KL 발산`)에만. |
| 빗금 | `/` | 대비되는 짝: `학습/추론`. 본문에서는 가운뎃점·쉼표를 우선한다. |

- **전각 부호 금지 (KO003):** 중국어 조판 부호 `（ ） ， ： ； ！ ？ 。 、 「 」`와 전각 물결표 U+FF5E를 쓰지 않는다. 원본 스킬이 중국어라 번역 잔재로 가장 흔하다. 논문·책 제목에 낫표(「」, 『』)를 쓰지 않고 큰따옴표로 쓴다(린터가 낫표를 전각 부호로 잡는다).
- 느낌표는 본문·해설에서 쓰지 않는다(§1.1, §1.4).

주요 출처: 국립국어원 『새국어생활』 제22권 제1호(2012) 특집 "번역과 국어"(원문 확인). 출처 열의 **(미확인)**은 공식 출처를 찾지 못한 관행 규칙이고, "린터"는 `lint-ko.py` KO101 규칙이다.

| ~에 있어서 | `~에서`, `~할 때` | 학습에 있어서 학습률은 중요하다 → 학습에서 학습률은 중요하다 | 새국어생활 2012, 린터 |

| ~되다 남발 | `~하다` | 성능이 향상되었다 → 성능이 올랐다 | 위키독스 2차 정리(국립국어원 자료 인용, 원문 열람 실패) |

| 대명사 과다 (그, 그것) | 생략 또는 명사 반복 | 그것은 그래디언트를 계산한다 → 이 층은 그래디언트를 계산한다 | 새국어생활 2012, 린터 |

| ~할 수 있을 것이다 | 단정 `~할 수 있다` | 성능을 높일 수 있을 것이다 → 성능을 높일 수 있다 | 새국어생활 2012(`-ㄹ 것이다` 빈도 지적), 린터 |
| ~고 있다 남용 | 현재형 | 이 방법은 KL 페널티를 사용하고 있다 → 이 방법은 KL 페널티를 쓴다 | 새국어생활 2012(보조용언 시제 빈도 지적) |
| ~적 남발, `~적인 ~적인` | 풀어 쓰기 | 효율적인 계산적 방법 → 계산 효율이 높은 방법 | (미확인), 린터 |
| ~을 통해 남용 | `~(으)로`, `~해서` | 실험을 통해 확인했다 → 실험으로 확인했다 (파일당 4회 이상이면 경고) | (미확인), 린터 |

| ~라는 것이다 | 삭제 | 핵심은 입력만 바꾼다는 것이다 → 핵심은 입력만 바꾸는 데 있다 | (미확인) |
| ~하지 않을 수 없다 | 단정 | 재검토하지 않을 수 없다 → 다시 검토해야 한다 | (미확인) |

- **허용:** 수학 서술의 피동 `정의된다`, `주어진다`, `계산된다`는 한국어에 정착했으므로 쓴다. `~되어진다`만 금지한다.
- 의미 손실이 생기면 번역투를 남긴다. 고쳐쓰기는 뜻을 바꾸지 않는 범위에서 한다.

## 7. 수식과 한글

- **인라인 수식 띄어쓰기:** 수식 앞은 한 칸 띄우고, 조사는 수식 뒤에 붙인다: `손실 $\mathcal{L}$은`, `여기서 $x$는`.
- **조사는 읽는 소리로:** `$x$는`(엑스는), `$n$은`(엔은), `$\theta$는`(세타는), `$\mathcal{L}$은`(엘은), `$x^2$은`(엑스 제곱은), `$\hat{y}$은`(와이 햇은), `$\pi_\theta$는`(파이 세타는), `$A_i$는`(에이 아이는), `$D_{\mathit{KL}}$은`(디 케이엘은). 읽기가 애매하면 기호 앞에 명사를 둔다: `정책 $\pi_\theta$를 갱신한다`. 린터는 수식 뒤 조사를 검사하지 않으므로 직접 확인한다.
- **식 참조:** `식 (3)`(식과 괄호 사이 한 칸). 조사는 숫자 읽기로: `식 (3)에서`, `식 (2)를`, `식 (1)과`. 그림·표는 `그림 2`, `표 1`.
- **변수 설명:** 식 바로 뒤에 `여기서 $\theta$는 모델 파라미터이다.` 여러 개면 `여기서 $x$는 입력, $y$는 정답 레이블, $\eta$는 학습률이다.`처럼 한 문장으로 잇는다.
- **블록 수식:** `$$ … $$`는 독립된 줄에 둔다. 앞 문장은 `손실 함수는 다음과 같다.`처럼 끝맺는다.
- 수식 안에 한글을 넣지 않는다. 필요하면 `\text{}` 대신 수식 밖에서 설명한다.
- **이름 있는 연산자도 이탤릭:** KaTeX는 `\cos`, `\sin`, `\max`, `\min`, `\arg`, `\log`, `\exp`, `\lim` 같은 이름 있는 연산자를 똑바른 글꼴로 그린다. 함수 이름은 글자이므로 `\mathit{cos}`, `\mathit{max}`, `\mathit{softmax}`, `\mathit{argmax}`로 쓴다(`\operatorname`도 쓰지 않는다). `\sum`, `\prod`, `\int`는 글자가 아닌 기호이므로 그대로 둔다. (KO112)
- **수식은 모두 이탤릭체:** 함수 이름·첨자 낱말도 `\mathit{}`로 쓴다(`\mathit{softmax}`, `d_{\mathit{model}}`). 벡터는 굵은 이탤릭 `\boldsymbol{q}`. `\mathrm`·`\mathbf`·`\text`·`\operatorname`은 쓰지 않는다(KO112). 그림 속 기호도 이탤릭이다: SVG는 `<text font-style="italic">`, 도식 라벨은 `<i class="mi">d</i><sub>k</sub>`(둘 다 KaTeX 수학 글꼴).
- **논문 식 번호:** 논문에 번호가 붙은 식은 블록 수식 오른쪽에 같은 번호를 단다: `$$ … \tag{1}$$`. 논문에 번호가 없는 식(유도 중간 단계, 보충 식)에는 번호를 달지 않는다. 같은 식을 다시 보일 때만 같은 번호를 쓴다.
- 수식 기호를 문장 주어로 연달아 쓰지 않는다. 처음에는 `학습률 $\eta$`처럼 이름과 함께 쓴다.

| ✗ | ✓ |
|---|---|
| $\theta$을 업데이트한다 | 파라미터 $\theta$를 갱신한다 |
| 식(3)에서 | 식 (3)에서 |
| where $\beta$ is a coefficient | 여기서 $\beta$는 KL 페널티의 세기를 정하는 계수이다. |
| $x$ 는 입력이다 | $x$는 입력이다 |

## 8. 영어 원문 인용

- 영어 원문 문장은 모듈당 1~2개 이내로 아껴 쓴다. 핵심 주장, 정의, 저자의 한계 인정처럼 원문 표현 자체가 의미 있을 때만 쓴다.
- 본문에는 **한국어 번역을 먼저** 쓰고, 원문은 `보충 설명` 콜아웃에 둔다. 원문 요소에는 `lang="en"`을 단다(린터는 `lang`이 ko가 아닌 요소의 문체 검사를 건너뛴다).
- 번역 인용은 큰따옴표로 묶고 출처(절 번호)를 밝힌다.

```html
<p>저자들은 “어텐션만으로 시퀀스 변환 모델을 만들 수 있다”고 주장한다(3절).</p>
<div class="callout callout-info animate-in">
  <div class="callout-icon">&#128161;</div>
  <div class="callout-content">
    <strong class="callout-title">보충 설명</strong>
    <p>원문: <span lang="en">“…”</span> (Section 3)</p>
  </div>
</div>
```

- 영어 문장을 번역 없이 본문에 두지 않는다. 논문 제목은 원제 그대로 두고 큰따옴표로 묶는다.
