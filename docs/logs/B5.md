# B5 로그: references/lint-ko.py 한국어 린터

산출물: `references/lint-ko.py`, `docs/lint-fixtures/bad.html`, `docs/lint-fixtures/good.html`, 본 로그.
사용법: `python3 references/lint-ko.py <코스 디렉터리|HTML> [--strict] [--json]` (ERROR 있으면 종료 코드 1, `--strict`는 WARN도 1).

### 행동 1: 파서 골격 (html.parser, 표준 라이브러리만)
- 근거: 빌드 환경에 추가 의존성을 두지 않기 위함. `<script>/<style>/<code>/<pre>`, KaTeX 렌더 결과(`class="katex*"`), `$…$`·`$$…$$`·`\(..\)`·`\[..\]` 수식은 한국어 문법 검사 대상이 아니므로 제외한다. 수식은 같은 길이의 공백으로 치환해 줄 번호가 어긋나지 않게 했다. 디렉터리 입력 시 `modules/`가 있으면 빌드 산출물 `index.html`은 중복이라 건너뛴다.
- 결과: 모든 이슈에 `파일:줄`, 규칙 ID, 심각도, 한국어 메시지와 수정 제안을 출력한다. `--json`은 같은 정보를 기계 판독용으로 낸다.

### 행동 2: ERROR 규칙 (KO001-KO004)
- 근거 KO001: `<html lang>`이 ko가 아니면 브라우저 하이픈·폰트 선택, 스크린리더 음성, `main.js` i18n 사전 선택(PLAN §1)이 모두 틀어진다. `<html`이 있는 파일에서만 검사한다.
- 근거 KO002: 원본이 중국어 스킬이라 번역 후 중국어/한자 잔재가 가장 흔한 결함이다(U+4E00-9FFF, U+3400-4DBF). 의도한 한자 병기(`한자(漢字)`)는 `lang="zh*"/"ja*"` 또는 `class="hanja"` 조상 요소 안에서만 허용한다. `data-definition` 속성값도 검사한다.
- 근거 KO003: `（ ） ， ： ； ！ ？ 。 、 「 」`은 중국어 조판 부호다. 한국어는 반각 부호를 쓴다. 문장 부호 규정(국립국어원 어문 규범 「문장 부호」, https://korean.go.kr/kornorms/regltn/regltnView.do?regltn_code=0001&regltn_no=3) 참고.
- 근거 KO004: `data-steps` JSON이 깨지면 단계별 인터랙션이 조용히 동작하지 않는다(번역 중 따옴표·쉼표 실수가 잦다).
- 결과: 아래 fixture에서 KO001 1건, KO002 2건(`中文`, data-definition 중국어), KO003 다수, KO004 1건 검출. `class="hanja"`, `<code>`, `<script>`, 수식 안의 한자·전각 문자는 검출되지 않음을 확인.

### 행동 3: WARN 규칙 (KO101-KO107)
- 근거 KO101(번역투): 국립국어원 '번역 투 표현' 순화 자료(https://www.korean.go.kr, 「알기 쉬운 공공 언어」·「번역 투 표현」 안내)가 지적하는 전형 패턴 — 영어 수동태 `에 의해`, `가지고 있다`, `에 있어서`, 이중 피동 `되어지다`, `에 대해(서)`, `로부터`, `~하는 것이 가능하다`, 대명사 직역 `그것은`, `~적인` 반복, 이중 복수 `~들의 ~들`. `을 통해`는 한두 번은 자연스러우므로 파일당 3회 초과일 때만 경고한다.
- 근거 KO102(문체 혼용): PLAN §1 "한 요소 안에서 섞지 않음". `<p>` 안에 합니다체와 해요체가 함께 있으면 경고한다(UI·퀴즈 피드백은 별도 요소라서 해요체 허용).
- 근거 KO103(괄호 앞 공백): PLAN §1 용어 표기 `한글 용어(English Term)`. 한글+공백+`(`+라틴 패턴을 잡는다.
- 근거 KO104(조사): 영문·숫자 뒤 조사는 읽는 발음 기준이다(PLAN §1). 대문자 약어(2자 이상)와 숫자 끝 토큰만 대상으로 마지막 글자 발음을 표로 판정한다(L엘·M엠·N엔·R알 → 받침 있음, 나머지 알파벳은 없음, 숫자 0영 1일 2이 3삼 4사 5오 6육 7칠 8팔 9구). `로/으로`는 받침 ㄹ이면 `로`(RNN으로, SFT로, 알(R)·일(1)·칠(7)·팔(8)·엘(L)은 ㄹ). LoRA·Transformer 같은 혼합 대소문자 단어는 단어 기반 발음이라 건너뛴다. 한계: `LLM이다`처럼 서술격 조사 `이`는 구분하지 않고 받침 기준으로만 본다.
- 근거 KO105(수+단위): 한글 맞춤법 제43항 "단위를 나타내는 명사는 앞 말과 띄어 쓴다"가 원칙이지만, 아라비아 숫자 뒤에서는 붙여 쓰는 것을 허용한다(https://korean.go.kr/kornorms/regltn/regltnView.do?regltn_code=0001&regltn_no=3 한글 맞춤법 제43항 다만 규정). 코스 전체의 일관성을 위해 `7개·45분·3단계`로 붙이는 쪽을 택해 `숫자 + 공백 + 단위`를 경고한다. `5 분석`처럼 단위로 시작하는 일반 단어는 뒤 글자 검사로 제외했다.
- 근거 KO106: 스킬 규칙 "텍스트 블록당 2-3문장"(content-philosophy). `[다요죠][.!?]` 종결 휴리스틱으로 4문장 이상을 경고한다.
- 근거 KO107: `.term`의 `data-definition`이 중국어/영어 그대로이거나 전각 괄호를 쓰면 툴팁에 잔재가 남는다(interactive-elements.md 예시 문구가 아직 중국어임에 유의).
- 결과: bad.html에서 KO101-KO107이 모두 최소 1회 검출됨.

### 행동 4: 오탐 수정
- 근거: 첫 실행에서 (a) good.html의 `GPT-3는`이 검출됐다 — 이는 린터가 옳다(3 = 삼, 받침 ㅁ → `GPT-3은`). fixture 원문을 고쳤다. (b) 하이픈 뒤 숫자(`GPT-3는`)가 숫자 단독 규칙에서 중복 검출되어 lookbehind에 `-`를 추가했다.
- 결과: 중복 검출 제거. 최종 bad.html은 ERROR 11건, WARN 24건, good.html은 0건 (아래 출력).

## 2차 수정: EBS 교재 문체

### 행동 1: KO102를 "합니다체/해요체 혼용"에서 "EBS 한다체 위반"으로 교체
- 근거: PLAN §1이 "본문 합니다체 / UI 해요체" 결정을 "EBS 교재 문체(본문 한다체 평서형)"로 대체했다. 따라서 혼용 여부가 아니라 합니다체(`~습니다/ㅂ니다/입니다/십시오`)와 해요체(`~요./요?/요!/죠`)가 본문에 나타나는 것 자체가 위반이다. 대상은 `p, li, td, th`, `class`에 callout/card/quiz-question이 들어간 요소, `data-definition`, `data-explanation-right/-wrong`이다. `~하시오`는 한다체 계열 지시문이라 허용한다. `필요/중요/주요/수요/개요` 등 `요`로 끝나는 명사는 해요체로 오인하지 않도록 제외했다.
- 예외 근거: PLAN §1 "연구 대화(채팅) 요소의 대사는 구어체 허용". interactive-elements.md의 대화 요소는 `chat-window / chat-messages / chat-message / chat-bubble / chat-sender`이므로, 클래스에 `chat|dialogue|message|bubble`이 포함된 조상 안은 검사하지 않는다. `lang`이 ko가 아닌 조상 요소 안(예: `<p lang="en">`)도 제외한다.
- 결과: bad.html에서 합니다체·해요체 모두 검출, 채팅 말풍선(해요체+`여러분`)과 `lang="en"` 문단은 미검출. 구현상 심각도는 WARN이다(요청에 심각도 지정 없음, `--strict`로 승격 가능).

### 행동 2: KO108 신설 (WARN) - 해설 칭찬·감탄
- 근거: PLAN §1 "해설·피드백: 정답/오답 표지 + 한다체 해설, 칭찬·격려 감탄문 없음". `data-explanation-right/-wrong`에서 `잘했, 훌륭, 멋져/멋지, 대단, 축하`와 문장 끝 `!`를 잡는다.
- 결과: bad.html 19행에서 검출.

### 행동 3: KO109 신설 (WARN) - '여러분'
- 근거: PLAN §1 "독자를 직접 부르는 여러분은 최소화". 본문 요소에서만 검사하고 chat 요소는 제외한다.
- 결과: bad.html 16행에서 검출, 채팅 말풍선의 '여러분'은 미검출.
