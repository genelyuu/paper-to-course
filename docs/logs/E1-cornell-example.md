# E1 작업 로그 (attention-ko 예제를 교재 지면 + 코넬식 페이지로 재구성)

작성일: 2026-11-25. 대상은 `examples/attention-ko/modules/*.html` 세 파일입니다. `styles.css`, `main.js`, `_base.html`, `_cover.html`, `_footer.html`은 수정하지 않았습니다. 레이아웃 기준은 `references/styles.css`의 "TEXTBOOK PAGE LAYOUT" 절입니다.

### 행동: 기준선 측정
- 근거: 바꾸기 전 상태를 알아야 어느 화면이 넘치는지 판단할 수 있습니다.
- 결과: `check-pages.py` 결과 페이지 21개 중 넘침 3개(module-0 확인 문제 1015px, module-1 수식 유도 822px, module-1 확인 문제 1170px), 코넬 아닌 화면 21개. `lint-ko.py --strict`는 ERROR 0, WARN 0이었습니다.

### 행동: 모든 화면을 `.screen.cornell` 구조(단서 칸, 노트 칸, 요약)로 바꿈
- 근거: 과제 요구사항(한 화면 = 한 페이지, 코넬식 노트). 각 페이지에 핵심 질문 2개(한다체 의문형) 또는 용어 정리(`dl`)와 한다체 한 문장 요약을 붙였습니다.
- 결과: 모듈마다 첫 페이지는 `.module-header` 바로 뒤에 두고 학습 목표 콜아웃을 단서 칸으로 옮겼습니다. 독립 화면이던 "핵심 정리"는 확인 문제 페이지의 단서 칸으로 합쳐 내용이 거의 없는 페이지(154~182px)를 없앴습니다. module-2의 "더 알아보기", module-1의 "보충 설명"도 단서 칸으로 옮겼습니다.

### 행동: 제목 접두어 제거와 코너 꼬리표 적용
- 근거: 문서가 "배경 지식 1." 식 번호 접두어를 금지하고, 코너 이름은 `corner-tag`로 쓰라는 요구사항.
- 결과: "배경 지식 N.", "탐구 자료: ", "논문 내용: " 접두어를 제목에서 모두 지웠습니다. 탐구 자료 5곳, 개념 체크 2곳, 확인 문제 5곳에 꼬리표를 달았습니다. 지식 지도 SVG 안의 "논문 내용: …" 상자 문구는 제목이 아니라 그림 내용이므로 그대로 두었습니다.

### 행동: 퀴즈 문항 번호와 배점 표기
- 근거: 수능 형식(번호 블록, 어려운 문항 [3점]) 요구사항.
- 결과: "1. ", "개념 체크. " 텍스트를 `<span class="q-num">`으로 바꿨습니다. [3점]은 module-0 2번(내적 비교), module-1 2번(<보기>형), module-2 2번(부정형 해석)에 붙였습니다. 선택지가 짧은 module-1 1번("① 4" 등)과 2번("① ㄱ" 등)은 `quiz-options row`로 바꿨습니다. `data-correct`, `data-explanation-*` 속성은 바꾸지 않았습니다.

### 행동: 첫 측정 후 넘치는 확인 문제 페이지 분할
- 근거: 첫 측정에서 module-0 확인 문제 894px(+129px), module-1 확인 문제 1130px(+365px). 문항 높이를 재 보니 2단 배치에서 한 칸 폭이 347px로 좁아 5지 선다 문항 하나가 267~311px, module-1의 <보기> 문항은 524px이었습니다. 제목을 빼도 넘쳤습니다.
- 결과: module-0은 `quiz-m0`(1, 2번)와 `quiz-m0-2`(3번)로, module-1은 `quiz-m1`(1, 2번)와 `quiz-m1-2`(3번)로 나눴습니다. 새 컨테이너마다 고유 id와 정답 확인·다시 풀기 버튼을 두었습니다. 분할 후 각각 603px/559px, 696px/582px.

### 행동: module-1 수식 유도와 개념 체크 분리
- 근거: 원래 한 화면이던 수식 유도 + 개념 체크가 822px로 넘쳤습니다.
- 결과: 개념 체크를 "크기 조정의 이유" 페이지로 분리하고 유도 3단계의 서술(분산 $d_k$, $\sqrt{d_k}$로 나누면 1)을 두 문장으로 다시 적었습니다(새 사실 없음). 수식 유도 633px, 개념 체크 553px.

### 행동: 노트 칸 폭에 맞춘 수식·의사코드 조정
- 근거: 1440×900 스크린숏에서 멀티헤드 식이 노트 칸 오른쪽 끝을 넘었고(노트 칸 776px, 원래 화면 800px), 의사코드 1·2줄의 주석이 줄바꿈되어 "입력", "계산"이 줄 번호 아래로 떨어졌습니다.
- 결과: 멀티헤드 식을 `gathered`로 두 줄로 나눴습니다. 의사코드 1줄을 `INPUT: Q, K, V, d_k  // 입력`, 2줄 주석을 `// 점수`로 줄였습니다(설명 칸 문장은 그대로). 다시 찍은 스크린숏에서 넘침과 줄바꿈이 없어졌고 멀티헤드 페이지는 719px입니다.

### 행동: 상호작용 요소의 최악 높이와 퀴즈 동작 확인
- 근거: `check-pages.py`는 첫 단계만 보인 상태를 잽니다. 단계별 풀이와 탭, 정답 해설이 펼쳐진 상태도 765px 안에 들어야 합니다.
- 결과: 헤드리스 Chrome 탐침으로 단계마다 높이를 잼. 내적 유도 615/638px, 어텐션 유도 633/612/645/632/632px, 제거 실험 탭 3개 모두 630px. 퀴즈 7개 모두 정답·오답 해설이 뜨고(문항마다 정답 1개, 오답 1개 번갈아 선택), 해설을 펼친 뒤 최대 728px(quiz-m1), 다시 풀기 후 선택·해설이 모두 지워짐. 페이지 오류(window error) 0건.

### 행동: 스크린숏으로 본 CSS 문제 기록(수정하지 않음)
- 근거: 과제 지시에 따라 CSS는 고치지 않고 보고합니다.
- 결과: 아래 네 가지를 발견했습니다.
  1. `.cue li::before` 원 표지가 단서 칸 안 콜아웃의 `ol` 항목(학습 목표, 핵심 정리)에도 붙어 "1. ○"처럼 번호와 원이 겹칩니다. 선택자를 `.cue > ul > li, .cue > ol > li`로 좁히는 것을 제안합니다.
  2. 문항이 하나뿐인 퀴즈(개념 체크 2개, 분할한 확인 문제 2개)도 2단 격자가 적용되어 오른쪽 칸이 비고 "다시 풀기" 버튼만 오른쪽에 떨어져 있습니다. `.cornell .quiz-container:has(> .quiz-question-block:only-of-type) { grid-template-columns: minmax(0,1fr); }`와 같은 예외를 제안합니다. 문항이 둘 이상일 때도 두 버튼이 서로 다른 칸에 있어 멀리 떨어지므로 버튼을 같은 칸에 나란히 두는 편이 낫습니다.
  3. `.quiz-options.row`의 `minmax(96px, 1fr)`은 라디오 원을 포함하면 좁아서 "⑤ ㄱ, ㄴ, ㄷ"가 두 줄로 꺾입니다. `minmax(120px, 1fr)` 또는 `.quiz-options.row .quiz-option { white-space: nowrap; }`를 제안합니다.
  4. `.quiz-question` 안 `.q-num` 뒤 문장이 두 줄이 되면 둘째 줄이 번호 블록 아래로 들어갑니다. 내어쓰기(`padding-left` + 음수 `text-indent`, 또는 `display:flex`)를 제안합니다.
